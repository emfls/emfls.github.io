Azure Key Vault API Retirement Checker

Audit ARM, Bicep, Terraform and SDKs before February 27, 2027. Key Vault management API versions older than 2026-02-01 retire on that date.

Check your Key Vault references

  1. Management REST. Check api-version on management.azure.com Key Vault requests.
  2. Infrastructure as code. Check ARM JSON apiVersion, Bicep type@version and Terraform AzAPI resource types.
  3. Management SDKs and CLI. Check the installed package or tool, or enter the effective API version used by your client.
  4. Data-plane runtime. Identify *.vault.azure.net requests for secrets, keys and certificates.

Azure RBAC default for new vaults

When a vault is created with API 2026-02-01 or later and enableRbacAuthorization is omitted, Azure defaults it to true. An existing vault keeps its current access model, Vault Access Policy or Azure RBAC, unless the setting is explicitly changed.

Review the deployment diff and verify least-privilege data-plane permissions for the workload identities. Treat any access-model change as a separate rollout. Microsoft Learn RBAC defaults

What the checker can establish

Compliance means a stable date meets the retirement cutoff or an installed client meets a documented baseline. For PowerShell management calls, that baseline is Az.KeyVault 6.6.1 or later. Verify that the exact API is published for the resource type and cloud, and check any request-level overrides. Preview management versions are flagged for migration even if their date is newer.

Paste literal Bicep resource headers, ARM JSON resource objects or templates, and AzAPI blocks. For values set by parameters, expressions, modules or the AzureRM provider, inspect the resolved deployment or request. A clean snippet does not cover callers outside the pasted text.

Frequently asked questions

What retires on February 27, 2027?

Azure Key Vault control-plane API versions older than 2026-02-01 retire. Audit the version on each management request and resource declaration, including child resources. Use a supported stable management API version at or above the cutoff.

Will my vaults or data-plane reads stop working?

Existing vaults remain in place. Calls to a vault.azure.net endpoint for secrets, keys and certificates use separate data-plane APIs and are outside this control-plane retirement. Data-plane preview APIs have their own lifecycle.

Does upgrading the API version switch existing vaults to Azure RBAC?

Existing vaults retain their access model unless enableRbacAuthorization is explicitly changed. Starting with API version 2026-02-01, newly created vaults default to Azure RBAC when the property is omitted.

Does the Terraform provider version tell me the API version?

AzAPI declares the management API in the resource type. For AzureRM, check the installed provider release and its resource documentation or inspect a sanitized request trace for the effective API version.
