BigQuery Storage API v1beta1 Shutdown Checker

Audit projects, gRPC clients and connectors before August 31, 2027, when all BigQuery Storage Read v1beta1 calls will return NOT_FOUND.

Why existing projects work while new or DR projects fail

Effective November 20, 2026, access to google.cloud.bigquery.storage.v1beta1 is restricted to Google Cloud projects that actively used v1beta1 between March 1, 2026 and August 31, 2026. The same legacy workload can keep working in production and fail in a new, staging or disaster-recovery (DR) project without that usage history.

Effective August 31, 2027, the BigQuery Storage Read v1beta1 API on bigquerystorage.googleapis.com shuts down for every project. BigQuery core REST jobs and queries (bigquery.googleapis.com/bigquery/v2) and BigQuery Storage Write API v1 are outside this shutdown.

Investigate NOT_FOUND by checking the API version, resource names, table existence, dataset location and caller permissions. Older archived v1beta1 RPC pages may show pre-announcement text. Use the November 25, 2026 BigQuery release notes for the shutdown timeline.

Verify the effective API before rollout

For custom clients, migrate beta imports and generated stubs to google.cloud.bigquery.storage.v1 and use the BigQueryRead service. Confirm the effective RPC in a deployed run. ReadSession, CreateReadSession and ReadRows can appear without a version in snippets.

For connectors, check the installed release and read configuration against the official vendor or Google release notes for a v1 default. In sanitized Cloud Audit Logs or Service Runtime (serviceruntime) API metrics, compare google.cloud.bigquery.storage.v1beta1.BigQueryStorage.* with google.cloud.bigquery.storage.v1.BigQueryRead.* for the same controlled read.

Frequently asked questions

Why can production work while a new or DR project fails?

Since November 20, 2026, only projects with active v1beta1 usage between March 1 and August 31, 2026 can access that API. A new, staging or disaster-recovery project without that history can fail even when the same workload still works in production.

What shuts down on August 31, 2027?

All calls to BigQuery Storage Read API v1beta1 will return NOT_FOUND. BigQuery core REST jobs and queries (bigquery/v2) and the BigQuery Storage Write API v1 are outside this shutdown.

How should I investigate NOT_FOUND from CreateReadSession or ReadRows?

Check the effective API version and the target table path, existence, dataset location and caller permissions. For ReadRows, also verify that the stream came from a valid read session. Compare the same v1 read in the existing and clean test or DR projects.

How do I confirm which API my connector uses?

Look up the deployed release and its read settings in the official vendor or Google release notes. Then run a controlled read and compare sanitized Storage API method names in Cloud Audit Logs or Service Runtime API metrics.
