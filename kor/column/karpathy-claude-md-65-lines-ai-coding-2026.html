텍스트 파일 하나가 전 세계 개발자를 열광시킨 이유

프레임워크도 라이브러리도 아닙니다. 심지어 코드 한 줄 없습니다. 그냥 마크다운 텍스트 파일 하나가 단 며칠 만에 깃헙 스타 10만 2,000개를 돌파했습니다. 이 파일의 이름은 CLAUDE.md입니다.

이 모든 것은 OpenAI 공동 창업자이자 테슬라 AI 디렉터였던 안드레 카파시(Andrej Karpathy)가 X(트위터)에 올린 한 게시물에서 시작됐습니다. 카파시는 AI가 코드를 작성할 때 반복적으로 저지르는 고질적인 문제 세 가지를 날카롭게 지적했고, 한 개발자가 그 메시지에서 핵심 원칙 네 가지를 뽑아 65줄짜리 CLAUDE.md 파일로 정리해 깃헙에 공개했습니다.

💡 CLAUDE.md란?

Claude Code가 프로젝트 작업 시작 전에 자동으로 읽어들이는 지시 파일입니다. 이 파일에 원칙을 적어두면 AI가 코드를 생성할 때 해당 원칙을 일관되게 따릅니다. 카파시의 원칙이 담긴 이 파일 하나만으로 Claude Code의 코드 품질이 드라마틱하게 향상된다고 알려지며 전 세계 개발자들이 열광하고 있습니다.

카파시가 짚은 AI의 3가지 고질병

카파시는 현재 AI 코딩 도구들이 공통적으로 가지고 있는 문제를 세 가지로 정리했습니다. 이 세 가지 병폐를 이해하면 왜 CLAUDE.md가 필요한지 자연스럽게 납득이 됩니다.

고질병증상실제 예시
잘못된 과정묻지도 않고 멋대로 해석 후 작업로그인 기능 요청에 JWT 방식으로 200줄 즉시 작성
코드 부풀리기몇 줄로 될 것을 1,000줄로 복잡하게 작성두 수를 더하는 함수에 인터페이스·추상클래스 추가
멋대로 수정요청하지 않은 코드 변경·주석 삭제버그 수정 요청 시 관련 없는 함수도 리팩터링

카파시가 내린 결론은 간단합니다. "명령하지 말고 성공 기준을 주고 지켜보라." 이 한 문장이 65줄 CLAUDE.md 전체의 철학을 담고 있습니다.

원칙 1 — Think Before Coding: 코딩 전에 먼저 생각하라

첫 번째 원칙은 추측하지 말고, 혼란스러운 부분을 숨기지 말고, 트레이드오프를 명확히 드러내라는 것입니다. AI가 실행하기 전에 가정한 내용을 명확히 밝히고, 여러 해석이 가능하다면 선택하지 말고 모두 제시해야 합니다.

예를 들어 "로그인 기능 추가해 줘"라는 모호한 요청을 받았을 때, 이 원칙이 없다면 AI는 즉시 JWT 기반 코드 200줄을 쏟아냅니다. 하지만 이 원칙이 적용되면 AI는 먼저 묻습니다.

✅ 원칙 적용 시 AI의 응답 예시

"인증 방식으로 JWT, 세션, OAuth 세 가지가 가능합니다. JWT는 서버리스 환경에 적합하고, 세션은 상태 관리가 필요하며, OAuth는 소셜 로그인을 지원합니다. 현재 프로젝트 구조상 어느 방식이 맞을까요?"

더 간단한 방법이 있다면 언급하고, 이해가 안 되는 부분이 있으면 멈추고 질문합니다. 이것만으로도 불필요한 코드 재작성이 대폭 줄어듭니다.

원칙 2 — Simplicity First: 문제를 해결하는 최소한의 코드만

두 번째 원칙은 단순함이 최우선이라는 것입니다. 요청한 기능 외에 추가 기능은 없어야 하고, 일회용 코드에는 추상화가 필요 없으며, 요청하지 않은 유연성이나 설정 가능성도 넣지 않습니다.

두 숫자를 더하는 함수가 필요할 때, 이 원칙이 없으면 AI는 인터페이스를 만들고, 구현 클래스를 정의하고, 팩토리 패턴을 추가합니다. 원칙이 적용되면 딱 세 줄짜리 함수 하나만 작성합니다.

📌 실제 원칙 원문 (요약 번역)

· 필요한 최소한의 코드만 작성하라
· 200줄을 썼는데 50줄로 줄일 수 있다면 다시 써라
· 시니어 개발자가 "이거 좀 복잡한데"라고 할 것 같으면 단순화하라

이 원칙은 토큰 절약, 유지보수 용이성, 코드 리뷰 효율까지 함께 높여줍니다. 복잡한 코드가 나쁜 코드인 경우가 대부분입니다.

원칙 3 — Surgical Changes: 꼭 필요한 것만, 본인이 작업한 곳만 수정

세 번째 원칙이 카파시의 통찰 중 가장 중요하다고 많은 개발자들이 꼽습니다. 수술하듯이 필요한 곳만 정확히 건드리고, 자신이 요청받은 범위 밖은 절대 손대지 말라는 것입니다.

어떤 함수의 버그만 고쳐달라고 했는데 AI가 작업하지도 않은 다른 함수를 수정하고, 주석 스타일을 바꾸고, 불필요한 임포트를 정리하면 — 코드 리뷰 범위가 폭발적으로 넓어지고 새로운 버그가 숨어들기 쉽습니다.

⚠️ 핵심 체크 질문 (원문)

"변경된 모든 줄이 사용자의 요청에 직접 연결되나요? 연결되지 않으면 손대지 마세요."

불필요한 코드를 발견하면 즉시 지우지 말고 "이 함수에 사용하지 않는 임포트가 있는데 정리할까요?"처럼 먼저 물어봐야 합니다.

기존 코드를 편집할 때 근처에 있는 주석이나 서식도 건드리지 않고, 기존 스타일을 그대로 유지합니다. 완벽한 것을 굳이 리팩터링하지 않습니다.

원칙 4 — Goal-Driven Execution: 성공 기준을 정의하고 검증될 때까지 반복

마지막 원칙은 카파시가 가장 강조한 "명령하지 말고 성공 기준을 주고 지켜보라"를 코드 레벨로 구체화한 것입니다. 과제를 검증 가능한 목표로 전환해 기준이 충족될 때까지 반복합니다.

나쁜 요청 방식좋은 요청 방식 (검증 가능)
버그를 수정해라버그를 재현하는 테스트를 작성하고, 그 테스트를 통과시켜라
이 코드 리팩터링해 줘리팩터링 전후에 기존 테스트가 모두 통과하는지 확인해라
성능 최적화해 줘응답 시간 200ms 이하를 달성하고 벤치마크로 검증해라

이 원칙이 적용되면 AI는 먼저 실패 케이스를 재현하는 테스트를 작성하고, 코드를 수정한 뒤, 테스트를 통과시키고, 기존의 다른 테스트도 전부 통과하는지 회귀 확인까지 합니다. "그럴 듯해 보이는 부분만 손대고 검증 없이 끝내는" 방식과는 완전히 다릅니다.

실제로 CLAUDE.md를 적용하는 두 가지 방법

카파시의 원칙이 담긴 CLAUDE.md를 내 프로젝트에 적용하는 방법은 크게 두 가지입니다.

방법 1 — Claude Code 스킬로 추가하기: Claude Code 터미널에서 아래 명령어로 마켓플레이스에 스킬을 추가한 뒤 설치합니다. 설치 후 /ka를 입력하면 카파시 가이드라인 스킬이 로드됩니다. 이 방식은 명시적으로 호출해야 적용됩니다.

# 전역(모든 프로젝트)에 적용
curl -o ~/.claude/CLAUDE.md https://raw.githubusercontent.com/forrestchang/andrej-karpathy-skill/main/CLAUDE.md

# 현재 프로젝트에만 적용
curl -o CLAUDE.md https://raw.githubusercontent.com/forrestchang/andrej-karpathy-skill/main/CLAUDE.md

방법 2 — 파일 직접 다운로드: 위 curl 명령어로 CLAUDE.md 파일을 내려받으면 됩니다. 주의할 점은 기존에 CLAUDE.md가 있다면 덮어씌워지므로 먼저 확인해야 합니다. 두 번째 방식으로 설치하면 해당 프로젝트에서 컨텍스트가 시작될 때마다 자동으로 원칙이 적용됩니다.

✅ 깃헙 레포지토리

원본 레포: github.com/forrestchang/andrej-karpathy-skill — 이미 10만 2,000개 이상의 스타를 받은 이 파일을 직접 열람하고 내용을 확인할 수 있습니다.

왜 이 단순한 파일이 10만 명을 움직였나

많은 사람들이 처음에는 의아해했습니다. "그냥 단순한 형태의 프롬프트 엔지니어링 아니야? 새로운 기술도 없고, 화려한 프레임워크도 없는데." 맞습니다. 65줄짜리 마크다운 파일입니다. 코드도 아닙니다.

그런데도 10만 명이 넘게 스타를 누른 이유는 한 문장으로 정리됩니다.

🔑 카파시의 핵심 통찰

"AI는 코드를 못 짜는 게 아니라 너무 잘 짭니다. 너무 빨리, 너무 자신있게 짭니다."

문제는 AI의 능력이 부족해서가 아니라 브레이크가 없다는 것이었습니다. CLAUDE.md는 그 브레이크를 달아주는 파일입니다.

4가지 원칙 적용 효과를 정리하면: ① 불필요한 변경 사항 감소 ② 과도한 복잡성으로 인한 재작성 방지 ③ Claude Code가 구현 전에 명확하게 질문 ④ 검증 단계가 자동으로 포함됩니다. 이 네 가지가 실제 개발 생산성에 직접적인 영향을 주기 때문에 전 세계 개발자들이 열광한 것입니다.

안드레 카파시가 지적한 AI 코딩의 3가지 고질병(잘못된 과정, 코드 부풀리기, 멋대로 수정)을 해결하기 위해 탄생한 65줄짜리 CLAUDE.md는 단 4가지 원칙으로 구성됩니다. ① 코딩 전에 먼저 생각하고 트레이드오프를 드러내라(Think Before Coding) ② 최소한의 코드만 짜라(Simplicity First) ③ 꼭 필요한 곳만 수정하라(Surgical Changes) ④ 성공 기준을 정의하고 검증될 때까지 반복하라(Goal-Driven Execution).
