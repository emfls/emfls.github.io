브라우저에서 평소 접속하던 사이트를 열었는데 갑자기 ‘연결이 비공개로 설정되어 있지 않습니다’라는 경고가 나타나거나, Chrome에 ‘시계가 너무 느립니다’ 또는 ‘시계가 너무 빠릅니다’라는 메시지가 나온다면 인터넷 회선보다 기기의 날짜와 시간을 먼저 확인해 보세요.

Google Chrome은 기기의 날짜·시간이 정확하지 않으면 NET::ERR_CERT_DATE_INVALID 같은 인증서 오류가 표시될 수 있다고 안내합니다. 사이트가 안전하게 연결되려면 인증서의 유효 기간을 확인할 수 있어야 하는데, 기기의 기준 시간이 잘못되면 정상적인 인증서를 잘못 판단하는 상황도 생길 수 있기 때문입니다.

그러나 모든 인증서 경고가 컴퓨터 시계 때문인 것은 아닙니다. 사이트 자체의 인증서가 만료됐거나, 회사의 네트워크 정책·보안 프로그램이 영향을 주는 경우도 있습니다. 이 글에서는 **'전체 사이트가 안 되는지', '한 사이트만 안 되는지', '화면 시각만 다른지'**를 먼저 나누어 불필요한 초기화를 피하는 방법을 설명합니다.

이 글은 2026년 11월 기준 Google Chrome, Microsoft, Apple, Google Android 공식 지원 문서를 바탕으로 작성했습니다. 운영체제 버전이나 제조사에 따라 메뉴 이름이 다를 수 있습니다.

1. 먼저 확인할 네 가지 증상

증상첫 번째로 점검할 항목바로 하지 말아야 할 일
Chrome에 '시계가 느림/빠름' 표시시스템 날짜와 현재 시간인증서 경고를 무시하고 접속
NET::ERR_CERT_DATE_INVALID 표시기기 시각 및 사이트의 인증서 문제임의로 인증서 설치
모든 HTTPS 사이트에서 동시에 경고기기 시각, 네트워크 또는 보안 프로그램운영체제 전체 초기화
특정 사이트 한 곳에서만 경고해당 사이트의 인증서와 관리 상태컴퓨터 전체 인증서 저장소 삭제

진단의 출발점은 특정 오류 문구입니다. 단순히 '인터넷 없음'이나 '사이트에 연결할 수 없음'만 표시되는 경우에는 이 글의 시계 조정만으로 해결되지 않을 수 있습니다.

공식 자료: Google Chrome — 일반적인 오류 메시지와 인증서 오류

2. '현재 시각', '날짜', '시간대'를 따로 확인하세요

컴퓨터 오른쪽 아래에 보이는 숫자만 맞추면 해결된다고 생각하기 쉽지만 다음 세 가지는 구분해야 합니다.

  1. 날짜: 연도·월·일이 맞는지 봅니다. 오래된 노트북을 켰더니 연도가 몇 년 전으로 돌아간 경우가 대표적입니다.
  2. 시각: 실제 시간과 기기가 표시하는 시간에 큰 차이가 있는지 확인합니다.
  3. 시간대: 대한민국에서 사용한다면 보통 서울(UTC+09:00) 시간대를 사용합니다. 해외여행을 다녀온 뒤 다른 지역 시간대가 남아 있지는 않은지 확인합니다.

시간대만 잘못 설정됐다면 보이는 현지 시각이 다르더라도 시스템의 절대 시간이 정상일 수 있습니다. 따라서 시간대 표시 오류와 인증서 유효기간 오류를 같은 문제로 단정하지 마세요.

다른 신뢰할 수 있는 기기의 시각과 비교해 보고, 운영체제에서 자동 시간 설정을 활성화하는 것이 기본적인 접근법입니다.

3. Windows 11에서 자동 시간 설정과 동기화하기

Microsoft는 Windows의 설정 → 시간 및 언어 → 날짜 및 시간 메뉴에서 자동 시간·시간대를 설정하도록 안내합니다.

  1. 시작 → 설정을 엽니다.
  2. 시간 및 언어 → 날짜 및 시간으로 이동합니다.
  3. 자동으로 시간 설정을 켭니다.
  4. 표준 시간대 자동 설정을 사용할 수 있다면 현재 위치에 맞는지 확인합니다. 잘못 감지되면 자동 설정을 끄고 (UTC+09:00) 서울을 선택할 수 있습니다.
  5. 동기화 항목에 지금 동기화가 보이면 실행합니다.
  6. 표시된 날짜와 시각이 맞는지 확인하고 Chrome 또는 Edge를 다시 열어 시험합니다.

기업·학교에서 관리하는 PC라면 날짜·시간 정책이 조직에 의해 제어될 수 있습니다. 해당 옵션이 비활성화돼 있으면 관리자에게 문의하세요.

설정이 이미 켜져 있는데 시간만 틀리다면? 인터넷이 정상 연결되어 있는지 확인한 뒤 동기화를 다시 시도합니다. Microsoft는 잘못된 날짜·시간이 Windows 업데이트에도 영향을 줄 수 있다고 설명하며, 관련 문제 해결 절차에서 '지금 동기화'를 안내합니다.

공식 자료: Microsoft — Windows 시간·날짜·시간대 설정, Microsoft — Windows 업데이트 문제 해결

4. Mac에서 자동 날짜·시간 설정 확인하기

Apple은 Mac에서 네트워크 시간 서버를 사용해 날짜와 시간을 자동으로 설정할 수 있다고 안내합니다.

  1. 왼쪽 상단의 Apple 메뉴 → 시스템 설정을 엽니다.
  2. 일반 → 날짜 및 시간으로 이동합니다.
  3. 자동으로 시간 및 날짜 설정을 켭니다.
  4. 네트워크 시간 서버 설정이 표시된다면 기존 설정을 확인합니다. 임의의 낯선 서버 주소로 바꾸지 않는 것이 좋습니다.
  5. 현재 위치를 사용하여 자동으로 시간대 설정 항목을 확인합니다.
  6. 자동 시간대가 잘못 지정되면 위치 서비스 상태를 확인하고, 필요하면 수동으로 현재 지역의 시간대를 선택합니다.
  7. 시간 표시가 바로잡혔다면 Safari·Chrome에서 같은 사이트를 다시 엽니다.

자동 시간대 설정은 기기 위치 서비스를 필요로 할 수 있습니다. 위치 서비스를 사용하지 않는다면 시간대를 수동 지정할 수 있지만, 그 자체로 인증서 오류가 해결됐다고 추정하지 말고 실제 날짜·시각이 맞는지 다시 확인하세요.

공식 자료: Apple — Mac에서 자동으로 날짜 및 시간 설정하기, Apple — Mac 날짜 및 시간 설정

5. 휴대전화에서도 같은 인증서 오류가 발생한다면

컴퓨터에서만 생기는 문제는 아닙니다. Google Chrome은 휴대전화의 날짜와 시간이 잘못 설정된 경우에도 시계·인증서 날짜 오류가 나타날 수 있다고 설명합니다.

아이폰

  1. 설정 → 일반 → 날짜 및 시간으로 이동합니다.
  2. 자동으로 설정 관련 옵션을 확인합니다.
  3. 현재 시간대와 날짜가 맞는지 살펴봅니다.
  4. 표시가 계속 잘못되면 Apple의 공식 안내에 따라 자동 설정 상태와 위치 서비스를 점검합니다.

일부 이동통신사나 국가·기기 관리 설정에 따라 자동 설정이 변경 불가능하게 표시될 수 있습니다. 회사의 관리 프로필이나 스크린 타임 제한이 원인일 수도 있으므로 제한을 임의로 우회하지 마세요.

갤럭시·안드로이드

기기마다 메뉴가 다르지만 일반적으로 설정에서 날짜 및 시간 자동 설정을 찾거나 Google이 안내하는 시계 앱 → 설정 → 날짜 및 시간 변경 경로를 확인할 수 있습니다.

  • 날짜 및 시간 자동 설정이 켜져 있는지 봅니다.
  • 시간대 자동 설정 상태를 확인합니다.
  • 해외 체류 중이라면 현재 지역 시간대가 맞는지 살펴봅니다.

공식 자료: Apple — 기기에서 시간 또는 시간대를 변경할 수 없는 경우, Google — Android 시간·날짜·시간대 설정

6. 한 사이트만 오류라면 내 컴퓨터 시계 탓이 아닐 수 있습니다

컴퓨터의 날짜와 시간이 정확한데도 특정 사이트에서만 인증서 날짜 오류가 난다면 다음과 같이 구분해 보세요.

점검 질문결과에 따른 해석
다른 유명 HTTPS 사이트는 정상 접속되나요?정상이라면 모든 웹 접속이 막힌 상황은 아닙니다
다른 기기의 다른 네트워크에서도 그 사이트가 오류인가요?동일하다면 사이트 측 인증서 문제 가능성을 검토할 수 있습니다
회사 PC에서만 오류인가요?프록시·보안 프로그램 등 조직 환경의 영향을 확인합니다
오류 화면에 인증서 만료가 표시되나요?사이트 소유자에게 인증서 관리 상태를 문의할 수 있습니다

이때 '고급 → 계속 진행' 같은 보안 우회 옵션을 사용하지 않는 것이 중요합니다. 개인 정보나 결제 정보를 입력하는 사이트라면 더더욱 경고를 무시해서는 안 됩니다.

브라우저 인증서 오류가 반복된다고 해서 인터넷에 게시된 불분명한 루트 인증서를 내려받아 설치해서도 안 됩니다. 회사 네트워크에서만 발생하는 문제는 조직 IT 관리자의 확인이 필요합니다.

공식 자료: Google Chrome — 인증서 및 보안 오류 안내

7. 시간이 맞는데도 동기화가 실패하는 경우

시간 설정을 자동으로 변경해도 즉시 정상화되지 않는다면 동기화가 실패하는 원인을 별도로 확인해야 합니다.

  1. 인터넷이 실제로 연결되어 있는지 확인합니다. 공용 와이파이라면 별도의 로그인 화면이 필요한 상태일 수 있습니다.
  2. VPN·프록시·방화벽 또는 회사의 관리 정책이 있는지 확인합니다.
  3. 관리형 기기라면 사용자 권한으로 서비스를 강제로 변경하지 않습니다.
  4. Windows의 '지금 동기화'나 Mac의 네트워크 시간 설정을 다시 확인합니다.
  5. 컴퓨터를 정상 종료하고 다시 켜서 설정이 유지되는지 확인합니다.
  6. 문제가 반복되면 제조사 또는 관리자의 진단을 받습니다.

전원을 껐다 켤 때마다 날짜가 크게 틀어진다면, 운영체제 설정 외에 기기의 시계 유지 기능 등 하드웨어 측 점검이 필요할 수도 있습니다. 그렇다고 사용자가 임의로 노트북을 분해하거나 부품을 교체할 필요는 없습니다.

또한 날짜·시간 문제를 고치기 위해 브라우저의 보안 검사 기능을 끄거나 인증서 검증을 비활성화하지 마세요.

8. 자동 동기화와 수동 설정 중 무엇이 좋을까요?

환경우선 권장되는 방법주의점
일반 가정용 Windows PC자동 시간 설정 후 동기화시간대도 별도로 점검
일반 Mac네트워크 시간 서버 자동 설정위치 서비스가 꺼져 있으면 시간대 수동 확인
해외여행 중인 노트북현재 현지 시간대 확인표시된 시간 차이와 실제 시계 오류 구분
회사·학교 관리 PC관리자 정책에 따른 설정정책을 임의로 변경하지 않기
인터넷 연결이 불가능한 기기현지 시각을 참고한 임시 수동 설정네트워크 복구 후 자동 설정으로 전환 검토

장기적으로는 시스템 시간을 자동으로 유지하는 편이 편리합니다. 다만 관리형 장비나 외부 네트워크 접근이 제한된 환경에서는 조직별 시간 동기화 정책을 따르는 것이 우선입니다.

9. 오류가 해결됐는지 확인하는 5분 테스트

해결 여부는 화면에 시계 숫자만 맞는지보다 원래 문제가 해결됐는지를 기준으로 판단해야 합니다.

  • ☐ 날짜의 연도·월·일이 정확한가?
  • ☐ 시각과 시간대가 현재 지역에 맞는가?
  • ☐ Windows 또는 Mac의 자동 시간 설정이 활성화돼 있는가?
  • ☐ 문제가 있던 사이트를 다시 열었을 때 인증서 경고가 사라졌는가?
  • ☐ 다른 HTTPS 사이트도 정상적으로 열리는가?
  • ☐ 컴퓨터를 다시 시작해도 날짜와 시간이 유지되는가?
  • ☐ 보안 경고를 우회하거나 불분명한 인증서를 설치하지 않았는가?

원래 오류가 사라졌다면 추가적인 네트워크 초기화나 인증서 삭제 작업은 필요하지 않습니다. 반면 정확한 시간으로 설정한 뒤에도 계속 경고가 발생한다면 시계 문제가 아닌 다른 원인을 진단해야 합니다.

10. 자주 묻는 질문

Q. NET::ERR_CERT_DATE_INVALID는 무조건 내 PC 시간이 틀려서 생기나요?

아닙니다. 컴퓨터나 휴대전화의 날짜·시간 오류가 한 가지 원인일 수 있지만, 실제 사이트 인증서의 유효기간 문제 등 다른 원인도 있습니다. 먼저 기기 시간을 확인한 뒤 여러 사이트에서 동일한 오류인지 비교하세요.

Q. 한국인데 시계가 9시간씩 차이 납니다. 무엇을 봐야 하나요?

시간대가 서울(UTC+09:00)인지 우선 확인하세요. 다만 시간대 표시가 잘못됐다는 사실만으로 인증서 오류의 원인이 확정되는 것은 아닙니다. 자동 시간 동기화와 실제 시스템 시간도 확인해야 합니다.

Q. Windows에서 자동 시간 설정을 켰는데 시간이 계속 틀립니다.

인터넷 연결을 확인하고 '지금 동기화'를 실행해 보세요. 관리형 PC라면 조직 정책의 영향을 받을 수 있습니다. 재부팅 후에도 설정이 반복적으로 틀어지면 장비 점검을 검토할 수 있습니다.

Q. Mac에서 자동 시간대 설정이 작동하지 않습니다.

Apple은 해당 기능에 위치 서비스가 필요할 수 있다고 안내합니다. 위치 서비스를 사용하지 않는 환경이라면 시스템 설정에서 현재 지역의 시간대를 수동으로 지정할 수 있습니다.

Q. 인증서 경고를 무시하고 접속하면 빨리 해결되나요?

경고를 넘기는 행위는 원인을 해결하지 않습니다. 연결 보안 문제가 남은 상태일 수 있으므로 시간 설정을 바로잡고 인증서 경고가 사라졌는지 확인하는 것이 먼저입니다.

Q. 컴퓨터의 시계가 틀리면 Windows 업데이트에도 영향을 주나요?

Microsoft는 잘못된 날짜·시간 설정이 Windows 업데이트를 방해할 수 있다고 안내합니다. 따라서 업데이트 장애를 점검할 때도 날짜·시간 설정과 동기화 상태를 확인할 가치가 있습니다.

11. 결론: 인증서를 건드리기 전에 시스템 시계를 확인하세요

웹사이트 보안 오류가 발생하면 브라우저를 삭제하거나 인증서를 임의로 설치하기 쉽지만, '시계가 느림/빠름'과 NET::ERR_CERT_DATE_INVALID 경고에서는 먼저 날짜·시각·시간대를 점검하는 것이 안전한 출발점입니다.

기기 시각 확인 → 자동 동기화 → 시간대 점검 → 사이트 재접속 → 다른 사이트와 비교 순서로 확인하세요. 시각이 정확한데 특정 사이트만 계속 실패한다면 서비스 제공자나 네트워크 관리자에게 문의하고, 경고 우회는 피하는 것이 좋습니다.
