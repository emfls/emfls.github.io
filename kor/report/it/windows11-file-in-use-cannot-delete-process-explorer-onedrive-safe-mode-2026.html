Windows 11에서 오래된 PDF나 동영상 파일을 지우려는데 **“다른 프로그램에서 이 파일을 사용 중이므로 작업을 완료할 수 없습니다”**라는 창이 나타나는 경우가 있습니다. 열려 있는 프로그램을 모두 닫은 것 같은데도 삭제가 되지 않는다면 무슨 문제일까요?

핵심은 파일을 화면에 띄워 놓은 앱과, 실제로 파일을 사용하고 있는 프로세스가 반드시 같지는 않다는 점입니다. 미리 보기, 동기화, 백업, 파일 압축 해제, 편집 프로그램의 백그라운드 작업이 파일을 열어 둔 상태일 수 있습니다. 이런 경우 폴더를 강제로 지우기보다 누가 파일을 사용하고 있는지 확인하고 정상 종료하는 절차가 먼저입니다.

이 글은 2026년 11월 기준 Microsoft의 Windows, OneDrive, Sysinternals 공식 안내를 바탕으로 작성했습니다. 설명은 삭제해도 되는 개인 파일을 대상으로 합니다. 회사 문서, 백업 원본, Windows 시스템 폴더, 실행 중인 서비스의 데이터 파일은 대상이 아닙니다.

2. 삭제 전 30초 확인: 정말 지워도 되는 파일인가?

먼저 파일이 무엇인지 확인하세요. 특히 메일 보관함, 가상머신 디스크, 작업 중인 영상, 프로젝트 데이터베이스, 회사 관리 파일은 단순한 임시파일이 아닐 수 있습니다.

  • 파일 이름과 확장자를 확인합니다.
  • 파일 탐색기의 주소 표시줄을 통해 전체 경로를 확인합니다.
  • 해당 파일이 다운로드한 복사본인지, 유일한 원본인지 구별합니다.
  • 다른 사람이 공유 폴더에서 사용 중일 가능성이 있는지 확인합니다.
  • 삭제 후 복구 가능성을 위해 필요하면 별도 백업을 남깁니다.

예시: 내 다운로드 폴더의 오래된 ZIP 파일과, 회사가 사용하는 공유 서버의 데이터베이스 파일은 삭제해도 되는지 판단하는 기준 자체가 다릅니다. 내용이 확실하지 않다면 삭제보다 보관이 우선입니다.

3. 가장 먼저 시도할 안전한 해결 순서

대부분의 경우 다음 순서를 먼저 시도할 수 있습니다.

  1. 파일을 열어 놓았을 수 있는 Word, Excel, 사진, 동영상 편집기, 압축 해제 프로그램을 확인합니다.
  2. 각 앱에서 작업 중인 내용을 저장합니다.
  3. 파일을 닫은 뒤 해당 앱을 정상 종료합니다.
  4. 파일 탐색기의 미리 보기 창을 사용 중이라면 잠시 끕니다. 파일 탐색기에서 보기 → 표시 → 미리 보기 창을 확인할 수 있습니다.
  5. 동일한 파일을 표시하는 다른 탐색기 창도 닫습니다.
  6. 몇 초 후 다시 삭제를 시도합니다.

정상 종료로 문제가 해결되면 추가적인 초기화·명령어 실행은 필요하지 않습니다. 미리 보기 창이 원인인지 확인하려면 창을 끈 상태에서만 재시험한 후, 필요하다면 다시 켜세요.

4. 프로그램을 닫았는데도 파일이 사용 중일 때

프로그램 창이 사라졌어도 백그라운드 프로세스가 남아 있을 수 있습니다. 이때는 Ctrl + Shift + Esc로 작업 관리자를 열어 확인할 수 있습니다.

  1. 작업 관리자의 프로세스 목록을 엽니다.
  2. 해당 파일을 열었을 법한 프로그램을 확인합니다.
  3. 그 프로그램에 저장하지 않은 작업이 없는지 먼저 확인합니다.
  4. 안전하다고 판단한 사용자 앱을 선택한 뒤 필요하면 작업 끝내기를 사용합니다.
  5. 다시 파일 삭제를 시도합니다.

작업 끝내기는 강제 종료에 해당할 수 있습니다. 파일을 편집 중이었다면 저장하지 않은 내용이 사라질 수 있으므로, 가능하면 앱 메뉴에서 정상 종료하는 것이 먼저입니다. 이름을 알 수 없는 Windows 서비스나 시스템 프로세스를 임의로 종료해서는 안 됩니다.

공식 참고: Microsoft — Windows PC 성능 개선을 위한 프로세스 확인

5. Windows 탐색기 자체가 파일을 붙잡고 있는 경우

탐색기는 파일 목록을 표시할 뿐 아니라 미리 보기, 썸네일, 속성 정보 등을 처리합니다. 따라서 다른 앱이 없어도 탐색기가 파일과 관련된 작업을 처리하는 경우가 있습니다.

다른 작업에 영향을 줄 수 있으므로 파일 탐색기를 다시 시작하기 전에 저장하지 않은 작업을 정리하세요.

  1. Ctrl + Shift + Esc를 눌러 작업 관리자를 엽니다.
  2. 프로세스 목록에서 **Windows 탐색기(Windows Explorer)**를 찾습니다.
  3. 항목을 마우스 오른쪽 버튼으로 클릭합니다.
  4. **다시 시작(Restart)**을 선택합니다.
  5. 작업 표시줄과 바탕화면이 다시 나타나면 원래 폴더에서 삭제를 재시도합니다.

작업 표시줄이나 탐색기 창이 잠시 사라졌다가 다시 표시될 수 있습니다. 탐색기 재시작으로도 해결되지 않는다면 같은 작업을 반복하기보다는 실제로 파일을 연 프로세스를 찾는 단계로 넘어가세요.

공식 참고: Microsoft — Windows의 탐색기 재시작 절차

6. Process Explorer로 파일을 사용하는 프로그램 찾기

파일을 사용 중인 프로그램을 정확히 모를 때는 Microsoft Sysinternals의 Process Explorer가 유용합니다. Microsoft는 이 도구를 어떤 프로세스가 특정 파일 또는 디렉터리를 열고 있는지 확인하는 도구라고 설명합니다.

2026년 10월 15일 공개된 Microsoft 공식 페이지에서는 Process Explorer v17.2를 안내하고 있습니다. 프로그램 버전은 이후 달라질 수 있으므로 다운로드 화면에서 다시 확인하세요.

이용 순서

  1. Microsoft 공식 Process Explorer 다운로드 페이지에 접속합니다.
  2. Microsoft가 제공하는 파일을 내려받아 실행합니다.
  3. 프로그램의 Find → Find Handle or DLL 기능을 선택합니다. 바로 가기 Ctrl + F를 사용할 수도 있습니다.
  4. 지우려는 파일의 이름 일부를 입력합니다.
  5. 검색 결과에서 해당 파일을 열고 있는 프로세스 이름과 경로를 확인합니다.
  6. 그 프로세스가 어떤 앱인지 확인한 뒤 해당 앱을 정상 종료합니다.
  7. 파일이 사용 중인 상태가 해제됐는지 확인하고 삭제를 다시 시도합니다.

예시: ‘회의녹화.mp4’라는 파일이 안 지워질 때 Process Explorer 검색에서 영상 편집기가 해당 파일을 열어 두고 있다는 사실을 알 수 있습니다. 이 경우 영상 편집기를 종료하는 것이 우선이지, Windows의 파일 시스템을 강제로 변경할 이유가 없습니다.

검색 결과가 없으면?

항상 프로세스 이름이 발견되는 것은 아닙니다. 잠금이 일시적이거나, 이름 검색이 맞지 않거나, 접근 권한이 제한된 경우도 있습니다. 결과가 없다고 해서 무조건 파일이 손상됐다고 단정하면 안 됩니다.

가장 중요한 주의점

Process Explorer에서 임의로 핸들을 닫는 작업은 하지 마세요. Microsoft의 관련 도구인 Handle 공식 문서는 핸들을 직접 닫는 작업이 앱이나 시스템을 불안정하게 만들 수 있다고 경고합니다. 사용자가 따라 해야 할 것은 프로세스를 식별하고 해당 앱을 정상 종료하는 절차입니다.

공식 참고: Microsoft Sysinternals — Process Explorer, Microsoft Sysinternals — Handle

7. OneDrive 폴더에서 삭제가 안 된다면

OneDrive의 동기화 폴더에 저장한 파일을 이동하거나 지우다가 오류가 발생했다면 일반 로컬 파일과 조금 다르게 접근해야 합니다.

Microsoft는 0x8007018b 오류가 OneDrive에서 사용 중인 파일의 삭제·이동·이름 변경을 시도할 때 나타날 수 있다고 안내합니다.

  1. 작업 표시줄의 OneDrive 구름 아이콘을 확인합니다.
  2. 현재 동기화 작업이 진행 중인지 확인합니다.
  3. 해당 파일이 Word·사진 앱 등 다른 프로그램에 열려 있다면 저장 후 종료합니다.
  4. OneDrive가 동기화를 완료하도록 기다립니다.
  5. 오류가 계속되면 OneDrive 메뉴에서 **종료(Quit OneDrive)**를 선택하는 공식 안내를 검토합니다.
  6. 문제가 해결됐다면 OneDrive를 다시 실행하고 동기화 상태를 확인합니다.

OneDrive 파일 삭제는 클라우드에도 영향을 줄 수 있습니다. 로컬 공간만 확보하려는 목적이라면 파일을 삭제하는 대신 **공간 확보(Free up space)**가 적절한지 먼저 확인해야 합니다. 특히 여러 기기에서 사용하는 원본을 지우지 않도록 주의하세요.

공식 참고: Microsoft — OneDrive 오류 코드 0x8007018b, Microsoft — 동기화 중인 파일 오류, Microsoft — OneDrive 파일 삭제

8. 재부팅 후 다시 삭제를 시도해 보세요

어떤 앱이 원인인지 바로 확인되지 않거나, 사용 중인 프로세스를 정상적으로 닫기 어렵다면 Windows 재시작이 더 간단할 수 있습니다.

  1. 진행 중인 문서와 작업을 저장합니다.
  2. 앱에서 로그아웃할 필요가 있는지 확인합니다.
  3. 시작 → 전원 → 다시 시작을 선택합니다.
  4. Windows가 다시 시작된 뒤 다른 앱을 많이 열지 않은 상태에서 해당 파일을 확인합니다.
  5. 파일 삭제를 재시도합니다.

이는 일부 일시적인 파일 사용 상태를 해소하는 데 도움이 될 수 있지만 모든 잠금이 풀린다는 보장은 없습니다. 시작 프로그램이 같은 파일을 다시 열거나 동기화 앱이 자동 실행된다면 재부팅 후에도 같은 오류가 나타날 수 있습니다.

공식 참고: Microsoft — PC 성능 문제 해결과 재시작

9. 안전 모드는 언제 사용할까요?

일반적인 재부팅 후에도 같은 오류가 반복되고, 시작 프로그램이나 타사 서비스가 문제를 일으키는 것으로 의심될 때 **안전 모드(Safe Mode)**를 진단에 활용할 수 있습니다.

Microsoft는 안전 모드를 Windows의 최소한의 파일과 드라이버로 시작하는 제한된 상태라고 설명합니다. 안전 모드에서 문제가 나타나지 않는다면 기본 Windows 구성보다 추가로 설치된 앱이나 서비스 등이 원인인지 살펴볼 단서가 됩니다.

안전 모드 진입 경로

  1. 설정 → 시스템 → 복구로 이동합니다.
  2. 고급 시작 옵션 → 지금 다시 시작을 선택합니다.
  3. Windows 복구 화면에서 문제 해결 → 고급 옵션 → 시작 설정 → 다시 시작을 선택합니다.
  4. 다시 시작된 화면에서 안전 모드 사용을 선택합니다.
  5. 문제가 발생한 개인 파일의 상태를 확인합니다.

환경에 따라 BitLocker 복구 키가 필요할 수 있으니 중요한 장비에서는 진입 전에 복구 수단을 확인하세요.

안전 모드라고 해서 Windows 시스템 파일을 강제로 지워도 된다는 뜻이 아닙니다. 삭제 대상이 명확한 개인 파일이고, 백업도 확인한 경우에만 작업하세요. 안전 모드에서도 지워지지 않는다면 권한, 파일 시스템, 조직 정책 등의 가능성을 전문가와 함께 점검하는 것이 안전합니다.

공식 참고: Microsoft — Windows 시작 설정과 안전 모드

10. 작업을 멈춰야 하는 경우

아래 상황이라면 ‘어떻게든 삭제하기’가 아니라 문제의 원인을 확인하는 것이 먼저입니다.

  • 경로가 C:\Windows, Program Files 등 시스템 영역에 속합니다.
  • 파일을 사용하는 프로세스가 Windows 서비스이지만 용도를 확인할 수 없습니다.
  • 회사 관리 장비이며 삭제 권한이 제한돼 있습니다.
  • OneDrive나 공유 드라이브에서 여러 사람이 파일을 사용합니다.
  • 파일이 데이터베이스, 메일 보관함, 가상머신 디스크, 백업 원본입니다.
  • 저장장치 오류가 의심되거나 다른 파일까지 읽기·쓰기 문제가 나타납니다.

특히 인터넷에서 찾은 강제 삭제 명령, 알 수 없는 유틸리티, 파일 권한 전체 변경 스크립트는 사용하지 않는 편이 좋습니다. 중요한 파일이라면 삭제보다 원인 확인과 보존을 우선하세요.

12. 자주 묻는 질문

Q. 파일을 열어 놓지 않았는데도 사용 중이라고 나옵니다.

파일 미리 보기, 백그라운드 앱, 동기화·백업 작업이 파일을 사용 중일 수 있습니다. 작업 관리자와 Process Explorer를 통해 실제 사용 프로그램을 확인해 보세요.

Q. 작업 관리자에서 '작업 끝내기'를 눌러도 괜찮나요?

사용자가 직접 실행한 앱이고 저장할 작업이 없다는 것을 확인했다면 하나의 해결 방법이 될 수 있습니다. 하지만 저장되지 않은 데이터는 사라질 수 있고, 시스템 프로세스를 임의로 종료해서는 안 됩니다.

Q. Process Explorer는 무료 도구인가요?

Microsoft Sysinternals에서 공식적으로 제공하는 유틸리티입니다. 다운로드는 Microsoft 공식 페이지에서 진행하고, 파일을 사용한 프로세스 식별 용도로 활용하세요.

Q. 잠겨 있는 파일의 핸들을 강제로 닫으면 더 빠른가요?

권장하지 않습니다. Microsoft는 핸들 강제 종료가 응용 프로그램과 시스템의 불안정을 유발할 수 있다고 경고합니다. 파일을 연 프로그램을 정상적으로 닫는 방식이 우선입니다.

Q. OneDrive의 파일을 삭제하면 클라우드에서도 사라지나요?

동기화된 파일을 삭제하면 클라우드와 다른 동기화 장치에 변경이 반영될 수 있습니다. 목적이 컴퓨터 용량 확보라면 파일 자체 삭제보다 '공간 확보' 기능을 먼저 살펴보세요.

Q. 재부팅해도 안 되는데 바로 안전 모드로 가야 하나요?

필수는 아닙니다. 재부팅 후에도 같은 앱이나 동기화 프로그램이 파일을 다시 열 수 있으므로 사용 프로세스를 확인하는 것이 유용합니다. 안전 모드는 원인 진단을 위한 추가 단계입니다.

Q. Windows 시스템 파일도 이 방법으로 삭제할 수 있나요?

이 글의 대상이 아닙니다. Windows 시스템 파일을 임의로 삭제하면 PC가 정상적으로 작동하지 않을 수 있습니다.

13. 결론: 강제로 지우지 말고 파일을 쓰는 프로그램부터 찾으세요

Windows 11에서 '다른 프로그램에서 사용 중' 오류가 발생했다면 실제 삭제 대상 확인 → 열린 앱 저장·종료 → 탐색기 미리 보기 확인 → 작업 관리자 → Process Explorer로 점유 프로그램 찾기 → OneDrive 동기화 확인 → 재부팅 → 필요하면 안전 모드 진단 순서로 접근하세요.

파일이 잠겨 있다는 것은 반드시 파일이 손상됐다는 뜻이 아닙니다. 대부분 먼저 확인해야 할 것은 무엇이 파일을 사용 중인지입니다. 원인을 확인한 뒤 해당 앱을 정상 종료하는 방식이 불필요한 강제 삭제나 데이터 손실을 줄입니다.
