쇼핑몰 주문 내역, 택배 송장, 고객 명단을 CSV 파일로 내려받아 엑셀에서 열었는데 한글은 깨지고 우편번호 '01234'는 '1234'로 변해 당황한 적이 있나요? 주문번호가 '1.23457E+19'처럼 표시되거나 제품코드 '1/2'가 날짜로 바뀌는 문제도 발생할 수 있습니다.

이런 현상은 하나의 오류가 아닙니다. 한글 깨짐은 문자 인코딩, 앞자리 0 소실은 데이터 형식, 모든 값이 한 열로 모이는 문제는 구분 기호를 우선 확인해야 합니다. 원인을 잘못 판단하고 파일을 덮어써 버리면 화면만 이상했던 데이터를 실제로 손상시킬 위험이 있습니다.

이 글은 Microsoft의 Excel·Power Query 공식 지원 자료를 바탕으로 2026년 11월 1일 기준 사용할 수 있는 방법을 정리했습니다. 중요한 것은 파일을 열기만 하는 것이 아니라 원본 값이 한 글자도 바뀌지 않았는지 검증하는 것입니다. Excel 버전, 언어 설정, 원본 CSV의 작성 방식에 따라 실제 메뉴와 변환 결과는 달라질 수 있습니다.

2. 복구보다 먼저 해야 할 일: 원본 CSV 보존

손상된 것처럼 보이는 파일을 곧바로 수정해 저장하지 마세요. 우선 다운로드한 CSV를 복사해서 원본 보관용과 작업용으로 나눕니다.

  1. 원본 CSV를 다른 이름으로 복사합니다.
  2. 수정했던 Excel 파일이 있다면 원본과 혼동하지 않게 분리합니다.
  3. 원본 파일을 Windows 메모장이나 신뢰할 수 있는 텍스트 편집기로 엽니다.
  4. 우편번호와 주문번호의 앞자리·뒷자리를 확인합니다.
  5. 한글도 원본 텍스트에서 정상인지 살펴봅니다.
  6. 실제 작업은 새 Excel 통합 문서에서 진행합니다.

텍스트 편집기에서도 값이 이미 잘못돼 있다면 원본 시스템에서 다시 내려받는 방법을 우선 검토합니다. 데이터가 바뀐 뒤 Excel의 표시 형식만 수정하는 방식은 원본 값을 복원하는 것과 다릅니다.

예를 들어 '01234'는 숫자 1234와 같은 의미라고 볼 수 없습니다. 제품코드 '00071'도 71과 같은 상품이라는 보장은 없습니다. 특히 20자리 주문번호는 합계나 평균을 낼 대상이 아니므로 처음부터 텍스트로 다루는 것이 적절합니다.

CSV는 대체로 쉼표로 구분하는 텍스트 파일입니다. 셀 색상, 열 너비, 텍스트 서식과 같은 통합 문서 속성을 함께 저장하지 않습니다. 어떤 프로그램으로 읽느냐에 따라 같은 CSV가 다르게 보일 수 있는 이유입니다.

4. 파일을 더블클릭하지 말고 Excel에서 데이터로 가져오기

중요한 CSV라면 Excel의 '파일 열기'보다 데이터 → 텍스트/CSV에서 경로를 추천합니다. 미리 보기에서 인코딩과 구분 기호를 확인하고 Power Query 편집기에서 열 형식을 지정할 수 있기 때문입니다.

  1. Excel의 빈 통합 문서를 엽니다.
  2. 데이터 탭으로 이동합니다.
  3. 데이터 가져오기 → 파일에서 → 텍스트/CSV에서를 선택합니다. 버전에 따라 '텍스트/CSV에서' 메뉴가 리본에 바로 보일 수 있습니다.
  4. 수정하지 않은 원본 CSV를 선택합니다.
  5. 미리 보기 화면에서 이름과 열 개수를 확인합니다.
  6. 중요한 식별번호가 있다면 바로 로드하지 말고 데이터 변환(Transform Data) 또는 편집 메뉴를 선택합니다.
  7. 열 형식을 확인한 뒤 닫기 및 로드로 가져옵니다.

Power Query는 CSV 파일의 열 이름이나 데이터 형식을 자동 감지할 수 있습니다. 따라서 미리 보기에서 한글이 정상이라고 숫자 코드까지 보존됐다고 판단하면 안 됩니다.

공식 근거: Microsoft — 데이터 원본에서 데이터 가져오기

5. 한글 깨짐 해결: UTF-8과 파일 원본 설정

문자가 깨지는 현상은 실제 CSV의 문자 인코딩과 Excel이 해석하는 문자 인코딩이 다르기 때문에 생길 수 있습니다. 한글이 들어 있는 업무용 CSV는 사용한 시스템에 따라 인코딩 방식이 달라질 수 있습니다.

해결 순서

  1. CSV 원본을 따로 보관합니다.
  2. Excel의 텍스트/CSV 가져오기 화면을 엽니다.
  3. 파일 원본(File Origin) 또는 문자 인코딩 선택 항목을 찾습니다.
  4. 원본이 UTF-8로 저장됐다면 UTF-8 계열 인코딩을 선택합니다. 일부 화면에서는 '65001: Unicode (UTF-8)'로 표시됩니다.
  5. 미리 보기에서 한글·영문·특수문자를 함께 확인합니다.
  6. 여러 인코딩을 시도했다면 가장 정확하게 원본 내용이 표시되는 설정을 사용합니다.
  7. 텍스트가 정상으로 보이면 다음 단계에서 열의 형식을 확인합니다.

Microsoft는 UTF-8 인코딩 CSV에 BOM(바이트 순서 표시)이 포함되어 있다면 Excel에서 정상적으로 열 수 있다고 안내합니다. BOM이 없는 UTF-8 CSV는 Power Query나 텍스트 가져오기 기능을 통해 여는 방법을 제시합니다.

BOM이 없다는 사실 자체가 파일 손상을 의미하지는 않습니다. BOM이 없더라도 정상적인 UTF-8 문서일 수 있습니다. 반대로 텍스트 편집기에 재저장할 때 잘못된 인코딩을 선택하면 원본을 다시 왜곡할 수 있으므로 원본 복사본에서만 시험하세요.

6. 모든 값이 한 열에 몰리면: 구분 기호 확인

원본에 이름·우편번호·주소가 각각 존재하는데 A열에 전부 붙어 들어온다면 CSV의 구분 문자를 Excel이 다르게 해석했을 수 있습니다.

CSV는 일반적으로 쉼표를 사용하지만 파일을 만든 시스템이나 지역 설정에 따라 세미콜론과 같은 다른 구분자가 쓰일 수 있습니다. 탭으로 구분된 텍스트를 CSV라고 부르는 경우도 있습니다.

  1. 원본을 텍스트 편집기로 열어 값 사이의 실제 문자를 확인합니다.
  2. Excel 데이터 가져오기 미리 보기로 돌아옵니다.
  3. 구분 기호(Delimiter) 옵션을 선택합니다.
  4. 쉼표·세미콜론·탭 중 실제 원본과 맞는 항목을 지정합니다.
  5. 미리 보기에서 열이 의도한 위치에 나뉘는지 확인합니다.

지역 설정을 바꿔 구분 기호를 해결하는 방법도 있지만, Microsoft는 Windows의 기본 구분 기호를 변경하면 다른 프로그램에도 영향을 줄 수 있다고 안내합니다. 특정 파일을 읽는 문제라면 해당 파일의 가져오기 옵션을 먼저 변경하는 것이 안전합니다.

주소나 설명문에 쉼표가 들어간다면 따옴표로 묶인 필드가 존재할 수 있습니다. 이런 경우 모든 쉼표를 일괄 치환하지 말고 가져오기 기능이 CSV 필드를 올바르게 처리하는지 확인하세요.

7. 앞자리 0 보존: Power Query에서 반드시 확인할 단계

우편번호 '01234', 제품코드 '00071'을 숫자로 바꾸면 앞의 0이 사라질 수 있습니다. 이런 값은 계산용 숫자가 아니라 문자열 식별자입니다.

Power Query에서 바르게 처리하는 방법

  1. 가져오기 미리 보기에서 데이터 변환을 누릅니다.
  2. 편집기에서 우편번호·상품코드·주문번호 열을 찾습니다.
  3. 열 머리글의 데이터 형식 아이콘 또는 홈 → 데이터 형식을 선택합니다.
  4. 해당 열을 **텍스트(Text)**로 지정합니다.
  5. 오른쪽의 **적용된 단계(Applied Steps)**를 확인합니다.
  6. 자동 생성된 변경된 형식(Changed Type) 단계가 이미 식별번호를 숫자로 바꾸고 있다면 해당 단계를 수정하거나 제거하고, 올바른 형식을 원본부터 적용합니다.
  7. 우편번호 '01234', 상품코드 '00071'이 그대로 보이는지 확인합니다.
  8. 닫기 및 로드로 결과를 가져옵니다.

가장 중요한 부분은 6번입니다. Power Query가 먼저 숫자로 변환해 앞자리 0을 없앤 뒤, 그 결과를 다시 텍스트로 바꿔도 '01234'가 아니라 '1234'만 남을 수 있습니다.

Microsoft는 Power Query가 비구조화된 데이터 원본에 대해 열 형식을 자동 추정하고 형식 변경 단계를 추가한다고 설명합니다. 자동 변경이 어떻게 적용됐는지 확인하는 것이 실수 예방의 핵심입니다.

8. 16자리 이상 주문번호는 왜 더 위험할까?

한글 깨짐은 화면에서 쉽게 발견할 수 있지만 긴 주문번호의 변형은 확인하기 어렵습니다. 제품이나 주문을 식별하는 코드가 과학적 표기법처럼 보이면 단순한 표시 문제인지, 실제 숫자 정보가 바뀐 것인지 구별해야 합니다.

Microsoft에 따르면 Excel의 일반 숫자 정밀도는 최대 15자리입니다. 16자리 이상의 숫자 데이터를 일반 숫자로 취급하면 뒤쪽 자릿수가 바뀔 수 있습니다.

원본 값잘못 처리할 경우안전한 방식
12345678901234567890일부 뒷자리 정보가 달라질 수 있음텍스트로 원문 유지
00123456789012345678앞자리 0과 뒤쪽 정밀도 손실 위험텍스트로 원문 유지
123E5지수 표기 숫자로 해석 가능코드 문자열 유지

이미 뒷자리가 바뀐 숫자는 셀 너비를 늘리거나 숫자 표시 형식을 조정해도 원래의 자릿수를 복구할 수 없습니다. 원래의 CSV 파일이나 원본 시스템과 다시 대조해야 합니다.

출처: Microsoft — 15자리 정밀도와 큰 숫자 처리

9. 제품코드가 날짜로 바뀐다면?

제품코드 '1/2'나 '3-4'가 날짜처럼 보이는 형식으로 변환되는 사례도 있습니다. Excel은 날짜를 쉽게 입력하도록 돕는 기능이 있기 때문에 특정 문자열을 사용자가 의도하지 않은 날짜로 판단할 수 있습니다.

이런 경우에는 데이터를 입력한 다음 형식을 고치는 것보다, 입력하거나 불러오기 전에 텍스트로 지정하는 것이 안전합니다.

  • CSV를 가져올 때: Power Query에서 해당 열을 텍스트로 읽고 적용된 단계를 확인합니다.
  • 직접 입력할 때: Ctrl+1 → 셀 서식 → 텍스트로 지정한 다음 입력합니다.
  • 적은 수의 값을 직접 입력할 때: 값 앞에 아포스트로피를 붙이면 Excel에서 텍스트로 취급할 수 있습니다.
  • 많은 행을 처리할 때: 수동으로 고치기보다 처음부터 원본 CSV를 알맞게 가져옵니다.

최신 Excel의 자동 변환 설정은 일부 제품·버전에서 제공됩니다. 모든 버전에서 날짜 자동 인식을 완전히 끌 수 있다고 단정하면 안 됩니다.

10. Excel 2024·Microsoft 365 자동 데이터 변환 옵션

Microsoft 365용 Excel, Excel 2024 등에서는 **자동 데이터 변환(Automatic Data Conversion)**을 제어하는 기능이 제공됩니다. Windows용 지원 제품에서는 파일 → 옵션 → 데이터에서 관련 항목을 확인할 수 있습니다.

공식 안내상 제어할 수 있는 주요 변환은 다음과 같습니다.

  • 앞자리 0을 제거하고 숫자로 바꾸는 동작
  • 16자리 이상을 일반 숫자로 처리해 일부 정밀도를 잃는 동작
  • E가 포함된 숫자처럼 보이는 문자열을 과학적 표기법으로 바꾸는 동작
  • 날짜로 해석될 수 있는 연속 문자열을 날짜로 바꾸는 동작
  • CSV·TXT 로드 시 자동 변환이 일어날 수 있다는 경고 표시

다만 이 설정을 끈다고 해서 파일 원본의 인코딩이 자동으로 수정되는 것은 아닙니다. 한글 깨짐은 별도로 해결해야 하며, 구분 기호도 확인해야 합니다.

또한 Excel 2019·2021과 같은 이전 제품에 최신 설정 메뉴가 그대로 있다고 가정하면 안 됩니다. Power Query로 중요한 열을 텍스트로 읽는 방법은 버전에 따른 자동 변환 옵션 차이와 별개로 유용합니다.

11. 이미 0이 사라진 파일을 복원할 수 있을까?

우편번호 '01234'가 '1234'로 바뀌었다면 표시 형식 '00000'을 적용해 다섯 자리로 보이게 할 수는 있습니다. 하지만 이것이 반드시 원본 복원을 의미하지는 않습니다.

코드의 길이가 정해져 있지 않거나, 원래 값이 '001234'인지 '01234'인지 알 수 없다면 숫자 1234만으로 원래 문자를 판단할 수 없기 때문입니다.

현재 상황권장 조치
원본 CSV가 남아 있음다시 가져오며 텍스트 지정
원본 시스템에서 재다운로드 가능원본 파일을 새로 내려받기
공식 코드 규격이 고정 자리수임규격과 원본 기록을 대조하며 재구성
16자리 이상 숫자가 변경됨원본 대조, 표시 형식만으로 복구 불가
변형 파일을 이미 덮어씀백업·이전 버전·원본 서비스 확인

실무적으로는 잘못된 결과를 보정하는 것보다 처음부터 정확히 가져오는 것이 안정적입니다. 전체 행을 임의로 수정했다가 오히려 정상적인 다른 코드를 바꿀 수 있으므로 원본을 우선 확보하세요.

12. CSV를 다시 저장하면 왜 같은 문제가 반복되나요?

CSV는 기본적으로 데이터 값을 교환하기 위한 텍스트 형식입니다. Excel 통합 문서의 여러 시트, 셀 서식, 수식과 같은 기능을 그대로 저장하기 위한 형식이 아닙니다.

따라서 CSV를 올바르게 읽은 뒤 셀 서식을 텍스트로 바꿔도, 다시 CSV로 저장하고 더블클릭하면 Excel이 해당 열을 새로 해석할 수 있습니다.

권장 방식은 다음과 같습니다.

  1. 원본 CSV는 그대로 보관합니다.
  2. 텍스트/CSV 가져오기로 올바른 데이터 형식을 적용합니다.
  3. 중요한 코드 열을 원본 문자와 대조합니다.
  4. **파일 → 다른 이름으로 저장 → Excel 통합 문서(.xlsx)**로 별도 저장합니다.
  5. XLSX를 다시 열어 데이터 형식과 식별번호를 재검수합니다.

CSV를 꼭 제출해야 한다면 상대방 시스템의 인코딩·구분 기호·열 처리 요구사항에 맞춰 내보내고, 그 시스템에서 다시 가져와 검증해야 합니다. Excel에서 만든 XLSX를 CSV로 바꾸었다는 사실만으로 정확성을 보장할 수 없습니다.

13. 현실적인 사례 세 가지

사례 1. 택배 송장 작업을 하다가 우편번호가 바뀐 경우

쇼핑몰에서 주문 CSV를 내려받아 곧바로 Excel로 연 뒤 우편번호가 '1234'처럼 네 자리로 표시됐다고 합시다. 배송지 데이터는 정확해야 하므로 원본 CSV를 다시 불러오고 우편번호 열을 텍스트로 지정합니다. 다른 주소·수취인 정보도 인코딩 문제가 없는지 함께 확인합니다.

사례 2. 거래처 명단에서 한글과 계좌 식별번호가 동시에 이상한 경우

회사명은 깨지고 긴 번호는 과학적 표기법으로 표시된다면 인코딩과 데이터 형식이 각각 문제일 수 있습니다. 한글부터 올바르게 보이게 한 뒤 식별번호 열을 텍스트로 지정합니다. 한글을 고쳤다고 두 번째 문제가 자동으로 해결되는 것은 아닙니다.

사례 3. 제품코드 '1/2'가 날짜처럼 바뀐 경우

원본에서 해당 문자는 코드였으므로 날짜로 바꿔서는 안 됩니다. Power Query에서 자동으로 추가된 형식 변경 단계를 살펴보고 필요하면 수정·제거한 뒤, 해당 열을 텍스트로 설정합니다. 마지막으로 원본 '1/2'와 가져온 값이 정확히 일치하는지 확인합니다.

세 사례 모두 화면 표시보다 원문과의 일치 여부를 기준으로 판단해야 합니다.

14. 데이터가 많은 경우의 실무용 검수표

수백~수천 행의 주문 파일을 다룬다면 다음 점검표를 권장합니다.

열 분리첫 줄과 예외 행의 열 수필드가 의도한 열에 배치
앞자리 001234·00071원문과 동일
긴 번호16자리 이상 식별번호모든 자릿수 일치

15. 매일 반복하는 업무라면 Power Query 변환 규칙 재사용

같은 형식의 CSV를 매일 불러온다면 Power Query의 변환 단계를 저장해 반복 적용할 수 있습니다. 코드 열의 텍스트 지정, 잘못 추정된 데이터 형식 수정, 구분자 선택을 매번 수동으로 반복하는 것보다 오류를 줄이는 데 도움이 됩니다.

다만 자동화해도 검수는 필요합니다.

  • 원본 CSV 열 이름이 바뀌면 쿼리가 제대로 작동하지 않을 수 있습니다.
  • 내보내기 시스템의 인코딩이 바뀌면 한글이 다시 깨질 수 있습니다.
  • 신규 제품코드에 날짜처럼 보이는 문자가 들어갈 수 있습니다.
  • 원본 행 수와 가져온 결과 행 수를 비교해야 합니다.
  • 새로 고침 후에도 앞자리 0과 긴 번호가 그대로 유지되는지 확인해야 합니다.

자동 변환 규칙을 만들었다는 사실이 원본 데이터의 영구적인 정확성을 보장하는 것은 아닙니다. 중요한 업무 데이터일수록 원본·변환 결과·최종 전달 파일을 구분해 보관하는 편이 좋습니다.

16. 자주 묻는 질문

Q. 메모장에서는 한글이 정상인데 엑셀에서만 깨집니다. 원본 파일이 손상된 건가요?

반드시 그렇지는 않습니다. 인코딩 해석이 다를 수 있으므로 Excel의 텍스트/CSV 데이터 가져오기에서 파일 원본을 확인하세요. 원본 복사본을 보존한 상태에서 진행하는 것이 좋습니다.

Q. UTF-8로 열면 우편번호의 앞자리 0도 복원되나요?

아닙니다. UTF-8은 문자 인코딩 문제를 다루는 설정입니다. 앞자리 0이 소실되는 문제는 숫자 자동 변환과 관련이 있으므로 텍스트 열로 가져와야 합니다.

Q. 이미 숫자로 바뀐 셀을 텍스트로 바꾸면 원래 코드가 복구되나요?

반드시 그렇지 않습니다. 특히 16자리 이상 숫자의 뒷자리가 실제로 변경된 경우에는 원본 CSV나 원본 시스템을 다시 확인해야 합니다.

Q. E+19로 보이는 숫자는 모두 손상된 데이터인가요?

그렇지는 않습니다. 표시 형식 때문에 지수 형태로 보일 수 있습니다. 다만 16자리 이상 식별번호를 일반 숫자로 변환했다면 정밀도 손실이 있을 수 있으므로 원본과 비교해야 합니다.

Q. 제품코드 1/2를 날짜로 바꾸지 않으려면 어떻게 하나요?

데이터를 가져오기 전에 해당 열을 텍스트로 지정하세요. 이미 날짜로 변했다면 변환 이력을 검토하고 원본에서 다시 가져오는 편이 정확합니다.

Q. CSV가 아닌 XLSX로 저장하면 무엇이 좋은가요?

Excel에서 확인한 열 서식과 여러 시트 같은 통합 문서 속성을 보관할 수 있습니다. 단, XLSX로 저장하기 전에 이미 데이터가 변형됐다면 저장 형식만 바꿔도 원래 정보가 되돌아오지는 않습니다.

Q. Mac에서도 같은 절차를 쓸 수 있나요?

Mac용 Excel도 데이터 가져오기 기능을 제공하지만 메뉴 위치와 지원 범위는 버전에 따라 다릅니다. 중요한 점은 파일의 인코딩·구분 기호·열의 텍스트 형식을 별도로 확인하는 것입니다.

Q. 온라인 서비스가 CSV만 받는다면 어떻게 해야 하나요?

상대 서비스가 요구하는 인코딩과 구분 기호를 확인하고, 다시 CSV로 내보낸 뒤 실제 제출 시스템에서 값이 보존됐는지 검증하세요. 특히 식별번호가 있는 경우에는 일부 표본이 아닌 오류 가능성이 높은 값도 확인해야 합니다.

17. 정리: 한글, 구분 기호, 식별번호를 각각 지켜야 합니다

CSV 파일을 안전하게 가져오는 권장 순서는 ① 원본 보관 → ② Excel 데이터 탭에서 텍스트/CSV 가져오기 → ③ 파일 원본 인코딩 점검 → ④ 구분 기호 확인 → ⑤ 식별번호 열을 텍스트로 지정 → ⑥ 자동 형식 변경 단계 점검 → ⑦ 원본과 데이터 비교 → ⑧ XLSX 별도 저장입니다.

화면에 표가 정상적으로 보이는 것만으로 데이터가 온전히 보존됐다고 볼 수 없습니다. 특히 우편번호·제품코드·주문번호처럼 숫자와 닮았지만 계산 대상이 아닌 값은 처음부터 텍스트로 읽는 것이 정확합니다. 이미 일부 숫자가 변형되었다면 임의로 0을 채우거나 서식을 바꾸기보다 원본 파일을 다시 확보하세요.
