Windows 11 업데이트가 0%에서 멈추거나, 설치 중 100%에 도달한 뒤 다시 실패하는 경우가 있습니다. 재부팅할 때 "변경 내용을 실행 취소하는 중"이라는 메시지가 나오거나 0x800f0922·0x80070002와 같은 오류 코드만 남기도 합니다.

이때 인터넷에 떠도는 복구 명령을 무작정 실행하거나 EFI 시스템 파티션을 삭제하는 것은 위험합니다. 업데이트 오류는 다운로드 실패, 설치 구성 요소 문제, 특정 버전의 알려진 문제를 먼저 구별해야 합니다.

이 글은 2026년 11월 1일 기준 Microsoft 지원 문서와 Windows 릴리스 정보를 바탕으로 10분 기본 진단 → 오류 코드 구분 → DISM·SFC → 복구 설치 순서로 안내합니다. 특히 2026년 9월 출시된 Windows 11 버전 26H2와 2026년 5월에 발생했던 0x800f0922 특정 업데이트 사례를 혼동하지 않도록 구성했습니다.

1. 먼저 증상과 오류 코드를 분류하세요

증상가능한 원인 범주첫 단계
다운로드 0%에서 움직이지 않음연결·다운로드·업데이트 서비스 문제인터넷과 문제 해결사 확인
설치 50~99%에서 오래 멈춤처리 시간·시스템 구성 요소 문제진행 여부 확인, 강제 종료 자제
재부팅 때 "변경 내용 실행 취소"설치 실패 후 롤백실패 KB 번호와 코드 기록

진행률이 몇 분 동안 바뀌지 않는다고 시스템이 완전히 멈췄다는 뜻은 아닙니다. Microsoft도 업데이트 설치 시간은 업데이트 크기와 기기·인터넷 환경에 따라 달라질 수 있다고 안내합니다.

2. 진단 전에 반드시 기록할 세 가지

① Windows 버전과 OS 빌드

Windows 키+R을 누르고 winver를 입력합니다. 표시되는 Windows 11 버전(예: 25H2 또는 26H2)과 OS 빌드를 메모합니다. 단순히 "윈도우11"이라는 정보만으로는 현재 필요한 패치가 무엇인지 정확히 판단하기 어렵습니다.

② 실패한 업데이트의 KB 번호

설정 → Windows 업데이트 → 업데이트 기록에서 실패한 업데이트를 찾습니다. KB로 시작하는 번호가 표시된다면 그대로 적습니다. 기능 업데이트와 월별 누적 업데이트는 다른 종류의 작업이므로 구별하세요.

③ 오류 코드와 발생 단계

0x800f0922와 같은 영문·숫자 조합, 실패가 발생한 시점, 화면에 뜬 메시지를 기록합니다. 다운로드 중인지, 설치 중인지, 재부팅 후인지에 따라 다음 행동이 달라집니다.

3. 2026년 Windows 11 26H2는 어떤 업데이트인가요?

Microsoft 공식 릴리스 정보에 따르면 Windows 11 버전 26H2는 2026년 9월 29일 일반 공급됐습니다. 2026년 10월 28일 릴리스 상태에서도 적격 장치에 대한 가용성을 안내했습니다.

다만 다음과 같은 차이를 알아야 합니다.

  • 26H2: 기존 지원 Windows 11 장치에서 제공될 수 있는 2026년 기능 업데이트입니다.
  • 26H1: Microsoft가 일부 새로운 기기용으로 구분한 버전입니다. 기존 24H2·25H2 PC의 일반적인 제자리 업그레이드 경로가 아닙니다.
  • 월별 KB 업데이트: 기능 업데이트와 별도로 배포되는 보안·품질 업데이트입니다.

따라서 26H2가 보이지 않는다고 바로 오류 코드 문제라고 결론 내리지 마세요. 먼저 winver에서 현재 버전을 보고, Windows 업데이트에 실제로 설치 제안이 있는지 확인합니다. 필요하면 Microsoft의 Windows 릴리스 상태에서 알려진 문제와 호환성 정보를 확인합니다.

공식 자료: Windows 11 릴리스 정보, Windows 11 26H2 알려진 문제

4. 가장 먼저 실행하는 10분 점검

Microsoft는 Windows 업데이트 문제를 해결하기 전 중요한 개인 파일을 백업하도록 안내합니다. 특히 아래 단계에서 복구 명령이나 다시 설치를 검토할 가능성이 있다면 더 중요합니다.

  1. 문서·사진·작업 중인 자료를 다른 위치에 백업합니다.
  2. 노트북은 충전기를 연결하고 안정적인 인터넷에 접속합니다.
  3. 설정 → 시스템 → 저장소에서 C: 여유 공간을 확인합니다.
  4. 필요하지 않은 외장 저장장치·도크·USB 기기는 안전하게 분리합니다.
  5. Windows를 정상적으로 다시 시작합니다.
  6. 설정 → Windows 업데이트 → 업데이트 확인을 실행합니다.
  7. 다시 오류가 나면 동일 오류 코드를 기록하고 다음 단계로 이동합니다.

업데이트마다 필요한 저장 공간은 다를 수 있습니다. 무조건 C:에 10GB만 있으면 된다는 단순 규칙을 적용하지 마세요. Windows가 부족한 저장 공간을 알리는 경우 저장소 설정과 공식 안내를 참고해야 합니다.

출처: Microsoft — Windows 업데이트 문제 해결

5. Windows 업데이트 문제 해결사를 먼저 실행하세요

Microsoft는 Windows 11에서 도움말 보기(Get Help) 앱의 Windows 업데이트 문제 해결사를 먼저 사용하도록 안내합니다. 설정을 통한 경로도 제공합니다.

  1. 설정 → 시스템 → 문제 해결로 이동합니다.
  2. 다른 문제 해결사를 엽니다.
  3. Windows 업데이트를 찾습니다.
  4. 실행 항목이 제공되면 안내에 따라 진단을 진행합니다.
  5. 완료 후 다시 Windows 업데이트를 확인합니다.

Windows 빌드와 설정에 따라 도움말 보기 앱으로 연결될 수 있습니다. 메뉴가 다르게 표시되면 Windows 검색에서 도움말 보기를 찾아 업데이트 문제 해결을 실행하세요.

문제 해결사가 완료됐다고 표시되어도 실제 설치 성공이 보장된 것은 아닙니다. 업데이트 기록과 Windows 버전을 확인해야 합니다.

6. 0x800f0922 해결법: 오류 코드보다 KB 번호가 먼저입니다

오류 코드 0x800f0922는 반드시 하나의 원인만 뜻하지 않습니다. Microsoft의 일반 도움말은 저장 공간, .NET Framework 또는 다른 구성 요소 관련 실패를 가능한 원인으로 안내합니다.

특히 2026년 5월 보안 업데이트 KB5089549에서는 별도 공식 사례가 있었습니다.

  • 일부 장치에서 EFI 시스템 파티션(ESP)의 여유 공간 부족 때문에 설치되지 않을 수 있었습니다.
  • 재부팅 과정에서 약 35~36%에서 실패하거나 변경 내용이 롤백되는 증상이 보고됐습니다.
  • Microsoft는 2026년 5월 26일 KB5089573으로 해당 문제를 해결했다고 기록했습니다.

하지만 이 사례는 특정 시기의 특정 KB에 대한 것입니다. 지금 발생한 모든 0x800f0922 오류가 ESP 용량 문제라는 뜻은 아닙니다.

확인 절차:

  1. winver로 버전을 기록합니다.
  2. 업데이트 기록에서 실패한 KB를 확인합니다.
  3. Microsoft 릴리스 상태에 같은 KB 관련 공지가 있는지 검색합니다.
  4. 해당 KB에 알려진 문제가 있다면 Microsoft의 해결 여부와 공식 지침을 따릅니다.
  5. 그렇지 않다면 일반 업데이트 문제 해결 및 오류 분석으로 진행합니다.

EFI 시스템 파티션을 임의로 삭제·포맷·크기 변경하지 마세요. 부팅에 영향을 주는 중요한 영역이며, 문제 원인 확인 없이 수정할 대상이 아닙니다.

공식 근거: Windows 11 24H2 해결된 문제

7. 0x80070002 해결법: 필요한 파일을 찾지 못하는 경우

Microsoft 기술 자료에서 0x80070002는 ERROR_FILE_NOT_FOUND, 즉 필요한 파일을 찾을 수 없다는 오류로 설명합니다. 그러나 이 코드만으로 누락된 파일이나 책임이 있는 프로그램을 확정할 수는 없습니다.

따라서 우선 다음 단계부터 진행하세요.

  1. Windows 업데이트 문제 해결사를 실행합니다.
  2. 인터넷·저장 공간·관리자 권한을 확인합니다.
  3. 컴퓨터를 정상적으로 다시 시작해 업데이트를 재시도합니다.
  4. 반복되면 공식 문서의 업데이트 캐시 정리 또는 시스템 파일 복구 단계를 검토합니다.
  5. 그래도 실패한다면 오류 메시지와 KB 정보를 기록해 Microsoft 지원이나 기기 제조사에 문의합니다.

외부 사이트에서 DLL이나 시스템 파일을 받아 Windows 폴더에 복사하는 방법은 권하지 않습니다. 신뢰할 수 없는 파일이 문제를 악화시킬 수 있습니다.

공식 코드 설명: Microsoft Learn — Windows 업데이트 설치 오류. 이 페이지는 서버 환경용 기술 문서이므로 일반 PC에서는 코드의 의미만 참고하고 해결 작업은 Windows 클라이언트 안내를 우선합니다.

8. 0x800f081f·0x80073712는 구성 요소 손상을 살펴보세요

Microsoft Learn은 0x800f081f를 필요한 원본을 찾지 못하는 상황, 0x80073712를 Windows 구성 요소 저장소 관련 오류로 설명합니다.

기본 점검 이후에도 실패하는 경우 시스템 파일 복구를 고려할 수 있습니다. Microsoft의 공식 안내는 DISM을 먼저 실행한 후 SFC를 실행하도록 설명합니다.

관리자 권한 명령 프롬프트에서 아래 순서를 사용합니다.

DISM.exe /Online /Cleanup-Image /RestoreHealth
sfc /scannow

실행 전 주의 사항:

  • 중요한 파일을 먼저 백업합니다.
  • 관리자 권한으로 명령 프롬프트를 엽니다.
  • DISM이 완료됐다는 메시지를 확인한 뒤 SFC를 실행합니다.
  • 검사 중 창을 닫거나 PC를 강제로 종료하지 않습니다.
  • DISM이 실패하면 같은 명령을 무작정 반복하지 말고 오류 메시지를 기록합니다.

DISM은 복구에 필요한 파일을 Windows 업데이트에서 가져올 수 있습니다. 업데이트 서비스 자체에 문제가 있으면 별도의 복구 원본이 필요할 수 있으므로 공식 지원 문서를 확인하세요.

공식 자료: 시스템 파일 검사기 사용, 일반적인 Windows 업데이트 오류

9. 업데이트 캐시가 손상된 것으로 보이면

Microsoft는 업데이트 파일 캐시가 손상된 경우 Windows 업데이트 서비스를 중지하고 SoftwareDistribution 폴더의 캐시를 정리한 후 서비스를 다시 시작하는 절차를 안내합니다.

기본 점검과 문제 해결사로 해결되지 않은 경우에 검토할 단계입니다.

  1. Windows 키+R을 누르고 services.msc를 입력합니다.
  2. 서비스 목록에서 Windows 업데이트를 찾습니다.
  3. 해당 서비스를 중지합니다.
  4. 파일 탐색기로 C:\Windows\SoftwareDistribution 폴더를 엽니다.
  5. Microsoft의 공식 지침에 따라 이 폴더 내부 캐시 항목을 정리합니다.
  6. 서비스 창으로 돌아가 Windows 업데이트 서비스를 다시 시작합니다.
  7. 업데이트 확인을 다시 실행합니다.

주의: 이는 C:\Windows 폴더 전체를 삭제하는 작업이 아닙니다. 지침과 경로를 정확히 이해하지 못했다면 파일을 임의로 삭제하지 마세요. 회사 PC는 관리자 정책을 확인해야 합니다.

공식 단계: Windows 업데이트 문제 해결

10. 업데이트 0%·99%·100% 멈춤을 어떻게 구분할까요?

다운로드와 설치, 재부팅은 서로 다른 작업입니다. 같은 0%라도 무엇을 처리 중인지에 따라 점검 방향이 다릅니다.

다운로드 0%에서 움직이지 않을 때

인터넷 연결, VPN·프록시·방화벽 등 네트워크 환경을 먼저 확인합니다. 회사 또는 학교 네트워크에서는 업데이트 서버 접근이 제한될 수 있습니다. Windows 업데이트 문제 해결사를 실행하고 문제가 계속되는지 확인하세요.

설치 51~99%에서 오래 걸릴 때

업데이트 크기와 기기 환경에 따라 처리 시간이 달라질 수 있습니다. 화면이 한동안 그대로라고 바로 강제 종료하지 말고 상태를 살핍니다. 동일한 문제가 반복되면 업데이트 기록과 문제 해결사를 확인합니다.

재부팅 후 설치를 취소할 때

Windows가 설치 실패 뒤 변경 내용을 되돌리는 과정일 수 있습니다. 다시 정상적으로 부팅된 뒤 KB 번호와 오류 코드를 기록합니다. 원인 없이 반복해서 강제 재부팅하지 마세요.

11. 회사 PC와 일반 가정용 PC의 해결법이 다른 이유

회사나 학교 컴퓨터는 Windows 업데이트가 조직의 관리 시스템을 통해 배포될 수 있습니다. 같은 오류 코드라도 일반적인 사용자 설정과 정책이 다를 수 있습니다.

특히 업데이트 서비스 중지, 캐시 정리, Windows 복구 설치와 같은 작업은 관리 정책에 영향을 받을 수 있습니다.

IT 담당자에게 전달할 정보는 아래처럼 정리하면 좋습니다.

  • Windows 버전과 빌드
  • 실패한 KB 번호
  • 오류 코드와 발생 시각
  • 다운로드·설치·재부팅 중 어느 단계에서 실패하는지
  • 사내 VPN·보안 프로그램 사용 여부
  • 이미 시도한 조치

관리되는 PC에서는 보안 프로그램이나 업데이트 정책을 임의로 해제하지 마세요.

12. 마지막 수단: 앱과 파일을 유지하는 Windows 복구 설치

기본 점검과 시스템 파일 복구로도 해결되지 않는 경우 Microsoft는 Windows 11에서 Windows 업데이트를 사용하여 문제 해결 기능을 안내합니다.

Microsoft 공식 문서에 따르면 이 기능은 현재 설치된 Windows 버전을 다시 설치해 시스템 파일과 구성 요소를 복구하면서 앱·파일·설정을 유지하도록 설계됐습니다.

지원되는 PC에서의 방법:

  1. 중요한 파일을 별도 저장소에 백업합니다.
  2. 설정 → 시스템 → 복구를 엽니다.
  3. Windows 업데이트를 사용하여 문제 해결을 찾습니다.
  4. 제공된다면 지금 다시 설치를 선택합니다.
  5. 화면의 안내를 확인하고 진행합니다.
  6. 전체 과정에서 PC를 전원 및 인터넷에 연결합니다.
  7. 다시 시작 후 Windows 버전과 업데이트 기록, 주요 앱·파일을 확인합니다.

이 기능이 모든 기기에서 제공되지는 않습니다. Microsoft는 회사·학교에서 관리하는 PC, 일부 Windows 버전이나 필요한 업데이트가 없는 장치에서는 이 옵션이 표시되지 않을 수 있다고 안내합니다.

앱과 파일을 유지하는 방식이라도 별도 백업 없이 실행할 것을 권하지 않습니다.

공식 문서: 현재 버전의 Windows를 다시 설치하여 문제 해결

13. 오류를 고치려다 더 큰 문제를 만드는 행동

  • EFI 시스템 파티션 삭제·포맷: 단지 0x800f0922가 표시됐다는 이유로 실행해서는 안 됩니다.
  • Windows 폴더 전체 삭제: 업데이트 캐시 정리와 Windows 시스템 폴더 삭제는 전혀 다릅니다.
  • 출처 불명의 DLL·업데이트 프로그램 다운로드: Microsoft 공식 배포 경로를 우선하세요.
  • 설치 진행 중 강제 전원 차단: 설치·복구 작업에 영향을 줄 수 있습니다.
  • BitLocker 복구 키 확인 없는 위험한 변경: 암호화가 사용 중이면 복구 키와 백업을 먼저 확인해야 합니다.
  • 비공식 버전 강제 설치: 기능 업데이트가 보이지 않으면 먼저 공식 릴리스 상태와 장치 호환성을 확인합니다.
  • 아무 진단 없이 초기화: 개인 파일과 앱에 영향을 줄 수 있으므로 낮은 위험의 단계부터 시작해야 합니다.

가장 중요한 원칙은 오류 코드가 같아도 원인이 같다고 단정하지 않는 것입니다.

14. 실제 사례로 보는 판단 방법

사례 A. Windows 11 25H2에서 26H2 설치 항목이 보이지 않습니다

winver에서 버전을 확인하고, Windows 업데이트에서 업데이트 확인을 실행합니다. Microsoft의 26H2 릴리스 상태와 관리 정책을 확인합니다. 26H1은 기존 25H2 PC를 위한 일반적인 제자리 업그레이드 버전이 아니라는 점도 구별하세요.

사례 B. 업데이트 후 35% 근처에서 롤백하고 0x800f0922가 나옵니다

업데이트 기록에서 KB 번호를 확인합니다. Microsoft는 2026년 5월 특정 보안 업데이트에서 EFI 시스템 파티션 용량 관련 문제를 공식 인정하고 수정했다고 안내했습니다. 그러나 다른 KB에서 같은 원인이 발생한다는 의미는 아닙니다. 파티션을 임의로 수정하지 마세요.

사례 C. 0x80070002만 나오고 다른 메시지가 없습니다

필요한 파일을 찾지 못하는 유형이라는 뜻을 확인한 후 문제 해결사, 연결, 저장 공간, 업데이트 캐시를 차례로 점검합니다. 중요한 작업 내용을 백업한 상태에서 공식 시스템 파일 복구 절차를 검토합니다.

15. 자주 묻는 질문

Q1. Windows 업데이트가 0%에서 멈추면 바로 강제 종료해야 하나요?

아닙니다. 다운로드 또는 설치 처리 중일 수 있습니다. 인터넷과 작업 상태를 확인하고 강제 종료를 먼저 시도하지 마세요.

Q2. 0x800f0922가 나타나면 무조건 EFI 파티션 크기를 늘려야 하나요?

그렇지 않습니다. Microsoft가 공개한 2026년 5월의 특정 문제는 EFI 시스템 파티션 용량과 연관이 있었지만, 다른 업데이트의 원인은 다를 수 있습니다. KB 번호를 확인해야 합니다.

Q3. 0x80070002는 무슨 뜻인가요?

Microsoft 기술 자료에서는 필요한 파일을 찾지 못하는 오류로 설명합니다. 어떤 파일이 문제인지는 추가 진단이 필요합니다.

Q4. DISM과 SFC는 어떤 순서가 맞나요?

Microsoft 공식 문서의 일반적인 시스템 파일 복구 절차는 DISM /RestoreHealth 실행 후 SFC /scannow 실행입니다.

Q5. 26H2는 이미 출시됐나요?

Microsoft 공식 릴리스 정보에 따르면 Windows 11 26H2는 2026년 9월 29일 일반 공급됐습니다. 실제 내 PC의 제공 여부는 Windows 업데이트와 릴리스 상태를 확인해야 합니다.

Q6. Windows 복구 설치를 하면 내 파일이 모두 삭제되나요?

Microsoft의 "Windows 업데이트를 사용하여 문제 해결" 기능은 앱·파일·설정을 유지하도록 설계됐습니다. 그러나 별도 백업을 확보하는 편이 안전합니다.

Q7. 회사 PC에서도 캐시를 지워도 될까요?

조직에서 업데이트와 보안 정책을 관리할 수 있으므로 관리자 승인 없이 서비스를 중지하거나 시스템 파일을 정리하지 마세요.

16. 최종 체크리스트

  • ☐ 중요한 파일을 별도 위치에 백업했다.
  • ☐ winver로 Windows 버전과 OS 빌드를 확인했다.
  • ☐ 실패한 업데이트의 KB 번호를 기록했다.
  • ☐ 오류 코드와 실패 단계를 기록했다.
  • ☐ C: 저장 공간과 인터넷 연결을 확인했다.
  • ☐ Windows 업데이트 문제 해결사를 실행했다.
  • ☐ 공식 릴리스 상태에서 해당 KB의 알려진 문제를 확인했다.
  • ☐ 필요한 경우에만 DISM·SFC 복구를 진행했다.
  • ☐ 업데이트 캐시 정리 경로를 정확히 확인했다.
  • ☐ EFI 시스템 파티션과 Windows 시스템 폴더를 임의로 삭제하지 않았다.
  • ☐ 마지막으로 업데이트 기록과 버전을 다시 확인했다.

결론: Windows 11 업데이트가 실패할 때는 Windows 버전, KB 번호, 오류 코드, 실패 단계 네 가지를 먼저 기록하는 것이 중요합니다. 업데이트 문제 해결사와 연결·저장 공간 점검에서 시작해 필요한 경우에만 업데이트 캐시 정리, DISM·SFC, 복구 설치로 진행하세요. 동일한 코드가 나타났다는 이유만으로 모든 PC에 동일한 고급 수리 방법을 적용해서는 안 됩니다.
