다운로드한 ZIP 파일을 더블클릭했는데 아무 반응이 없거나, 압축을 푸는 도중 “예기치 않은 오류”, “액세스가 거부되었습니다”, “CRC 오류”라는 메시지가 나타날 때가 있습니다. 겉으로 보기에는 모두 ‘압축파일 오류’지만 해결 방식은 다릅니다.

특히 암호가 걸린 압축파일을 Windows 기본 탐색기로 열 수 없는 문제와 전송 도중 실제 압축파일이 손상된 문제는 구분해야 합니다. 암호 해제 프로그램을 무작정 설치하거나, 원본을 지우고 다시 압축을 시도하면 해결 기회를 잃을 수 있습니다.

이 글은 Windows 11에서 ZIP·7z·RAR 파일을 열지 못할 때 ‘파일 형식 → 암호 → 무결성 → 저장 경로 → 권한’ 순서로 원인을 좁히도록 새로 구성한 실전 가이드입니다. 2026년 11월 1일 기준 Microsoft와 7-Zip 공식 문서를 바탕으로 작성했습니다.

1. 먼저 오류 문구를 확인하세요: 증상별 첫 번째 행동

나타나는 증상우선 확인할 원인첫 번째 행동

비밀번호를 입력해도 계속 오류잘못된 암호·암호화 방식·손상발신자에게 암호 확인, 지원 도구 점검

중요: 오류 코드 하나만으로 원인이 확정되지는 않습니다. 예를 들어 0x80004005는 여러 상황에서 나타날 수 있으므로, ‘암호가 틀렸다’고 단정하지 마세요.

2. 원본을 지키는 ‘실패해도 손해 없는’ 3단계

문제 해결 전에 아래 세 가지만 먼저 지키면 데이터 손상 위험과 헛수고를 줄일 수 있습니다.

  1. 원본 압축파일은 그대로 보관합니다. 이름을 바꾸거나 다시 저장해야 한다면 복사본으로 작업합니다.
  2. 새 폴더를 만든 뒤 그곳에 추출합니다. 예를 들어 C:\Temp\zip-test처럼 짧고 쓰기 권한이 있는 경로가 좋습니다. 기존 동일 이름 파일을 덮어쓰지 마세요.
  3. 같은 오류가 다시 나면 메시지를 기록합니다. 정확한 파일명, 확장자, 오류 문구, 실패 시점을 적어 두면 원인 분류가 쉬워집니다.

압축파일이 중요한 업무 문서라면 오류가 난 압축을 여러 번 ‘수리’하는 것보다 보낸 사람에게 정상 원본을 다시 요청하는 것이 더 확실한 경우가 많습니다.

3. 정상적인 ZIP 파일은 Windows에서 어떻게 풀까요?

Windows 파일 탐색기의 기본 기능으로 일반적인 ZIP 파일을 추출할 수 있습니다.

  1. 파일 탐색기에서 ZIP 파일을 찾습니다.
  2. 압축파일을 마우스 오른쪽 버튼으로 클릭합니다.
  3. ‘모두 추출’ 메뉴가 보이면 선택합니다.
  4. 저장할 폴더를 지정하고 추출합니다.
  5. 추출한 폴더에서 대표 문서·사진을 실제로 열어 결과를 확인합니다.

파일 한두 개만 필요한 경우 압축파일을 열어 필요한 항목을 일반 폴더로 끌어 복사할 수도 있습니다. 단, 압축파일 안의 문서를 열었다고 해서 반드시 별도의 정상 저장본이 만들어진 것은 아닙니다. 수정할 문서는 먼저 압축을 해제한 폴더에 복사하세요.

4. ZIP·RAR·7z·TAR는 같은 압축파일일까요?

모두 데이터를 묶어 보관하는 데 사용되지만 내부 구조와 기능이 같지는 않습니다. 단지 확장자 이름을 .zip으로 바꾼다고 다른 형식이 ZIP으로 변환되지 않습니다.

Microsoft에 따르면 Windows 11 버전 24H2는 ZIP·RAR·7z·TAR 보관 형식을 지원합니다. 다만 지원 형식이라고 해서 모든 압축 알고리즘과 암호화된 보관파일을 기본 탐색기에서 처리할 수 있다는 뜻은 아닙니다.

형식흔한 사용 상황점검할 부분
ZIP이메일 첨부·여러 파일 묶기암호 보호·다운로드 손상
7z대용량 자료·높은 압축률전용 도구·암호화·분할 파일
RAR배포 자료·여러 조각으로 나눈 파일분할 구성·암호화·형식 지원
TAR개발·백업 파일 묶음.tar.gz 등의 복합 확장자

Windows 업데이트 상태와 프로그램 버전에 따라 사용 가능한 탐색기 메뉴가 달라질 수 있습니다. “RAR은 무조건 별도 프로그램이 필요하다”거나 “Windows에서는 암호 ZIP도 전부 열린다”는 식의 단정은 피해야 합니다.

5. 비밀번호가 걸린 ZIP·7z에서 기본 탐색기가 실패한다면

Windows 11 24H2의 기본 압축 기능에는 암호화된 보관파일 작업을 지원하지 않는 제한이 있다고 Microsoft가 명시합니다. 그러므로 압축파일이 정상이고 비밀번호도 정확한데 기본 탐색기에서 추출이 실패할 수 있습니다.

이때는 순서대로 확인합니다.

  1. 먼저 보내는 사람이 제공한 비밀번호와 파일 형식을 확인합니다.
  2. 첨부파일을 신뢰할 수 있는 출처에서 받은 것인지 점검합니다.
  3. 7-Zip 공식 사이트 등 신뢰할 수 있는 공식 배포처에서 지원 도구를 받습니다.
  4. 7-Zip 파일 관리자로 해당 압축파일을 열고 추출합니다.
  5. 암호 입력창이 나오면 정확히 입력하고, 추출된 파일을 실제로 확인합니다.
  6. 계속 오류가 난다면 암호 오류뿐 아니라 손상된 파일·지원하지 않는 방식도 의심합니다.

7-Zip은 7z와 ZIP의 AES-256 암호화를 지원하고 RAR 파일의 해제를 지원한다고 공식 사이트에 설명합니다. 다만 모든 형식의 생성 기능까지 같은 것은 아닙니다. 예를 들어 7-Zip의 공식 지원 표에서 RAR은 해제 지원 형식으로 구분됩니다.

비밀번호를 모르는 경우: 파일 소유자나 발신자에게 확인하는 것이 우선입니다. 정체가 불분명한 ‘비밀번호 즉시 해제’ 웹사이트에 회사 문서·개인정보가 담긴 압축파일을 업로드하지 마세요.

6. “암호가 틀림”과 “CRC 오류”는 어떻게 구별하나요?

암호 입력 단계에서 거부되는 문제와 추출 중 데이터 검사에 실패하는 문제는 다르게 접근해야 합니다. CRC는 데이터가 원래 상태와 일치하는지 확인하는 데 사용하는 오류 검출 방식입니다.

  • 암호 입력 전부터 파일을 열 수 없다면 파일 형식·헤더·다운로드 상태를 먼저 점검합니다.
  • 암호 입력 직후 실패한다면 올바른 암호인지 확인하되, 암호화 형식이 도구와 맞지 않는 가능성도 생각합니다.
  • 목록은 보이는데 추출 중 CRC 또는 Data Error가 발생하면 내부 데이터 손상 가능성을 우선 조사합니다.
  • 일부 파일만 실패한다면 그 파일을 다시 구할 수 있는지, 발신자가 원본을 갖고 있는지 확인합니다.

7-Zip 공식 문서는 압축 내부 파일 목록은 보이지만 Test 또는 Extract에서 CRC/Data Error가 발생하는 상황과, 보관파일 자체를 열지 못하는 상황을 구분합니다. 두 경우 모두 복구가 항상 가능한 것은 아닙니다.

7-Zip의 ‘Test’ 기능을 사용해 압축 내부 검사 결과를 확인할 수도 있습니다. 단, ‘검사가 성공했다’는 것과 추출된 문서 내용이 완전하게 올바르다는 것은 같은 검증이 아닙니다.

7. CRC 오류가 나면 재다운로드가 먼저인 이유

압축을 내려받는 도중 연결이 끊기거나 전송 파일이 불완전하면 압축 내부의 데이터 검사에 실패할 수 있습니다. 원본 보관파일의 데이터가 손상됐다면 컴퓨터에서 다른 추출 프로그램을 실행해도 정상 원본이 자동으로 생기지는 않습니다.

실행 순서는 다음과 같습니다.

  1. 압축파일의 현재 크기를 확인하고, 제공자가 고지한 원본 크기나 체크섬이 있다면 대조합니다.
  2. 신뢰할 수 있는 원래 배포처에서 새 파일을 다시 내려받습니다.
  3. 새 파일은 기존 파일과 구분되는 다른 이름 또는 폴더에 저장합니다.
  4. 가능하면 다운로드에 사용한 네트워크나 저장 장치를 바꾸어 비교합니다.
  5. 다시 내려받은 파일에서도 같은 지점이 실패하면 발신자에게 원본을 재압축해 전달해 달라고 요청합니다.

체크섬 값이 다르면 파일 내용이 원본과 일치하지 않는다는 근거가 되지만, 체크섬이 없다고 해서 반드시 손상됐다는 뜻은 아닙니다.

일부 복구 프로그램이 손상 파일의 일부 내용을 꺼낼 수는 있으나, 복구된 데이터가 원본과 동일하다는 보장은 없습니다. 중요한 자료는 복구본만 믿고 원본을 삭제하지 마세요.

8. ‘경로가 너무 깁니다’ 오류는 무엇 때문인가요?

압축 안에 폴더가 여러 겹으로 들어 있으면 실제 추출 경로가 예상보다 길어집니다. 예를 들어 다음과 같은 상황입니다.

다운로드 → 2026업무자료 → 최종버전 → 부서별 정리 → 프로젝트별 정리 → 첨부파일 → 문서.pdf

Windows의 일부 Win32 프로그램은 경로 길이 제한과 관련된 문제를 만날 수 있습니다. Microsoft는 전통적인 MAX_PATH 값이 260자이며, 더 긴 경로 지원은 운영체제 설정뿐 아니라 애플리케이션 자체 지원 여부에 따라서도 달라진다고 안내합니다.

가장 먼저 해볼 방법은 레지스트리 수정이 아닙니다.

  1. 압축파일을 C:\Temp 같은 짧은 경로에 복사합니다.
  2. C:\Temp\out 등 짧은 새 폴더로 추출합니다.
  3. 성공했다면 압축 내부 폴더 구조가 길었는지 확인합니다.
  4. 필요한 파일만 적절한 위치로 옮깁니다.

무조건 레지스트리를 수정해 긴 경로를 활성화하는 방법은 권하지 않습니다. 긴 경로 설정을 켜더라도 지원하지 않는 앱의 문제까지 해결되는 것은 아닙니다.

9. ‘액세스가 거부되었습니다’ 또는 대상 폴더 생성 실패

압축파일에 문제가 없어도 추출할 폴더에 대한 쓰기 권한이 없다면 오류가 발생할 수 있습니다.

가능한 원인으로는 회사 PC의 보안 정책, 읽기 전용 매체, 다른 프로그램이 열고 있는 파일, 파일명 충돌, 보안 프로그램의 보호 동작 등이 있습니다. 어느 하나가 원인이라고 단정할 수는 없습니다.

다음 순서로 점검하세요.

  1. 추출 대상을 바탕화면이나 문서 폴더 등 본인이 쓰기 가능한 로컬 폴더로 바꿉니다.
  2. 기존에 같은 이름의 파일이 열려 있지 않은지 확인합니다.
  3. 저장 공간이 충분한지 점검합니다. 압축된 크기와 해제된 크기는 다릅니다.
  4. 회사·학교 PC라면 관리자 정책을 임의로 해제하지 말고 IT 담당자에게 문의합니다.
  5. 정상 파일인지 불분명한 상태에서 보안 프로그램을 통째로 끄거나 관리자 권한으로 반복 실행하지 않습니다.

가장 위험한 대응은 출처를 확인하지 않은 압축파일을 무조건 관리자 권한으로 실행하는 것입니다. 단순한 문서 묶음인지, 실행파일이 포함돼 있는지도 먼저 살펴보세요.

10. .001·.002 또는 part1.rar 파일이 여러 개라면

여러 파일이 이어지는 분할 압축은 일반 ZIP 하나와 구조가 다를 수 있습니다. 파일을 일부만 받으면 첫 번째 조각을 열더라도 끝까지 추출하지 못합니다.

확인할 것은 모든 조각이 존재하는지, 파일 이름이 일관되는지, 같은 폴더에 있는지입니다.

예를 들어 archive.7z.001, archive.7z.002 형태로 받았다면 첫 번째 파일만 존재하는 상태에서 전체 압축이 풀릴 것으로 기대하면 안 됩니다. archive.part1.rar, archive.part2.rar 같은 다른 이름 패턴도 있으므로 정확한 추출 시작 파일과 방법은 만든 프로그램 및 배포자의 설명을 따릅니다.

주의사항도 있습니다.

  • 조각 중 하나라도 손상됐다면 전체 해제가 실패할 수 있습니다.
  • .001 파일의 확장자를 임의로 .zip으로 바꾼다고 합쳐지지 않습니다.
  • 모든 조각을 받은 후 신뢰 가능한 추출 도구로 작업합니다.
  • 발신자가 지정한 파일명·순서를 임의로 바꾸지 않는 편이 안전합니다.

11. ‘파일을 보관파일로 열 수 없습니다’가 뜬다면

7-Zip의 메시지 ‘Can not open file as archive’는 단순히 비밀번호가 틀렸다는 뜻으로 해석해서는 안 됩니다. 공식 7-Zip FAQ는 잘못된 ZIP 헤더가 이와 같은 문제를 일으킬 수 있다고 설명합니다.

가능한 점검 항목은 아래와 같습니다.

  • 실제 파일 형식과 확장자가 일치하는가?
  • 원본 제공자가 파일 크기나 체크섬을 안내했는가?
  • 다운로드가 완전히 끝나기 전에 파일을 옮기지 않았는가?
  • 압축파일이 아니라 HTML 오류 페이지나 다른 콘텐츠가 저장된 것은 아닌가?
  • 마지막 분할 파일이 누락된 것은 아닌가?
  • 받은 자료가 개인 또는 회사 메신저에서 자동 변환된 파일은 아닌가?

특히 파일 이름만 ZIP처럼 보이게 바뀌었다면 정상 압축 프로그램을 여러 개 설치해도 해결되지 않을 수 있습니다. 발신자에게 새로 압축해 재전송을 요청하는 것이 우선입니다.

공식 자료: 7-Zip FAQ

12. 파일을 온라인 압축 해제 사이트에 올려도 될까요?

이 문제는 ‘무료인가’보다 어떤 파일을 누구의 서버에 보내는가가 중요합니다.

가족 사진, 금융 문서, 주민등록번호가 있는 파일, 업무 문서, 계약서처럼 민감한 내용이 들어 있다면 온라인 추출 사이트 업로드를 피하는 편이 안전합니다. 파일을 서버에 보낸 순간 그 서비스의 보관·삭제·접근 정책을 검토해야 하기 때문입니다.

신뢰할 수 있는 공식 프로그램을 설치해 내 PC에서 로컬로 추출할 수 있다면 그쪽이 적합한 경우가 많습니다. 그러나 로컬 프로그램 역시 공식 사이트가 아닌 광고성 다운로드 페이지에서 받으면 위험할 수 있습니다.

압축파일을 받았을 때 '압축 해제 도구 설치'를 유도하는 정체불명의 파일은 실행하지 마세요. 일반적인 ZIP 문서를 읽기 위해 발신자가 제공한 별도의 EXE 실행파일을 반드시 설치해야 하는 것은 아닙니다.

13. 자주 하는 실수 6가지

  1. 확장자만 변경: .rar를 .zip으로 바꿔도 내부 형식은 변하지 않습니다.
  2. 원본 바로 삭제: 손상 여부가 확정되기 전에 원본을 없애면 비교할 자료가 사라집니다.
  3. 암호 오류를 손상으로 단정: 지원하지 않는 암호화 방식일 수도 있습니다.
  4. CRC 오류를 암호 문제로 단정: CRC는 데이터 불일치와 관계될 수 있습니다.
  5. 압축파일 내부에서 문서 편집: 변경 내용을 안전하게 저장하지 못할 수 있습니다.
  6. 재부팅보다 먼저 시스템 설정 변경: 짧은 추출 경로와 재다운로드로 해결할 문제에 불필요한 권한·레지스트리 수정부터 시도하지 않습니다.

14. 실제 상황별 해결 시나리오

사례 A: 공공기관에서 내려받은 ZIP이 Windows 탐색기에서 열리지 않는다

① 파일 출처가 해당 기관의 공식 페이지인지 확인합니다. ② ZIP을 짧은 경로로 복사합니다. ③ 암호가 걸린 파일인지 공식 안내를 확인합니다. ④ 암호화된 ZIP이라면 Windows 기본 도구의 지원 한계를 고려해 7-Zip 같은 지원 도구를 사용합니다. ⑤ 끝까지 실패하면 기관에 정상 파일을 다시 요청합니다.

사례 B: 친구가 보낸 8GB 자료를 풀다가 CRC 오류가 난다

① 현재 받은 파일을 삭제하지 않고 별도로 보관합니다. ② 발신자의 원본 크기·체크섬과 비교합니다. ③ 파일을 재전송받습니다. ④ 다시 실패하면 원본 압축파일 자체를 새로 만들어 달라고 요청합니다. ⑤ 추출됐다 해도 주요 파일의 정상 여부를 확인합니다.

사례 C: 회사 프로젝트 폴더에서만 추출 실패한다

① 회사 보안 정책을 해제하지 않습니다. ② 허용된 짧은 로컬 경로에서 시험합니다. ③ 성공하면 경로 길이나 대상 폴더 권한을 분리해서 점검합니다. ④ 실패하면 오류 문구와 파일 경로를 IT 담당자에게 전달합니다.

사례 D: .7z.001 파일 하나만 받았다

① 전체 분할 파일 수를 확인합니다. ② 누락된 파일을 모두 확보합니다. ③ 파일을 같은 폴더에 둡니다. ④ 배포자가 안내한 시작 파일을 추출 프로그램에서 선택합니다. ⑤ 임의로 확장자를 바꾸거나 파일을 합치는 프로그램을 무작정 실행하지 않습니다.

15. 자주 묻는 질문

Q1. Windows 11은 이제 RAR 파일을 기본으로 풀 수 있나요?

Windows 11 버전 24H2의 공식 지원 목록에 RAR이 포함돼 있습니다. 다만 OS 버전이나 암호화 여부 등에 따라 제한이 있을 수 있습니다.

Q2. 비밀번호는 맞는데 오류가 나는 이유는 무엇인가요?

암호화된 압축을 기본 탐색기가 지원하지 않거나, 압축파일 내부 데이터가 손상됐거나, 다른 형식 오류가 있을 수 있습니다. 암호가 틀린 것만이 원인은 아닙니다.

Q3. CRC 오류가 나오면 무조건 복구 불가인가요?

그렇지는 않습니다. 다만 복구 가능 여부와 범위는 손상 부위에 따라 다르며 완전 복구를 보장할 수 없습니다. 다시 받거나 원본을 다시 압축해 전송받는 방법이 우선입니다.

Q4. 무료 압축 프로그램을 설치해도 되나요?

도구 자체의 유료·무료 여부보다 공식 배포처인지가 중요합니다. 7-Zip은 공식 사이트에서 무료 오픈소스 프로그램으로 안내됩니다.

Q5. ZIP 파일 안에 비밀번호가 걸린 PDF가 있다면?

ZIP 압축파일의 암호와 내부 PDF 파일의 암호는 서로 다른 보안 계층일 수 있습니다. ZIP 추출에 성공하더라도 PDF를 열 때 별도 암호를 요구할 수 있습니다.

Q6. 바이러스 검사가 문제가 되는 것 같은데 꺼야 하나요?

원인 확인 없이 보안 기능을 끄지 마세요. 파일 출처를 검증하고, 보안 경고가 발생했다면 검사 결과와 조직 정책을 우선 확인해야 합니다.

Q7. Windows에서 ZIP을 다시 압축하면 손상이 복구되나요?

손상된 압축파일 자체를 새로 압축한다고 그 안의 원본 데이터가 자동 복원되지는 않습니다. 정상 원본 파일을 확보해야 합니다.

16. 5분 최종 점검표

  • ☐ 압축파일 원본을 별도로 보관했다.
  • ☐ 파일이 ZIP·RAR·7z·TAR 중 어떤 형식인지 확인했다.
  • ☐ 암호화 여부와 Windows 기본 도구 지원 한계를 확인했다.
  • ☐ 파일을 짧고 쓰기 가능한 경로에서 추출해 봤다.
  • ☐ CRC·Data Error가 나오면 재다운로드 또는 원본 재전송을 시도했다.
  • ☐ 분할 압축이라면 조각이 모두 있는지 확인했다.
  • ☐ 주요 문서가 실제로 열리는지 검증했다.
  • ☐ 민감한 압축파일을 모르는 온라인 사이트에 업로드하지 않았다.

핵심 정리: 압축파일이 안 열린다고 해서 반드시 파일이 손상된 것은 아닙니다. Windows 기본 탐색기의 암호화 제한, 파일 형식 지원, 실제 데이터 손상, 긴 경로, 접근 권한 문제를 나누어 확인해야 합니다. 무엇보다 중요한 것은 원본을 보호하고, 실패 원인을 확인한 뒤 다음 조치를 선택하는 것입니다.
