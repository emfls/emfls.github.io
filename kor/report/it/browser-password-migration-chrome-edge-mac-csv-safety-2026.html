PC를 바꾸거나 Chrome에서 Microsoft Edge로 갈아탈 때 예상치 못하게 어려운 작업이 있습니다. 바로 여러 사이트에 저장된 비밀번호를 빠짐없이 옮기는 일입니다. 즐겨찾기와 방문 기록은 쉽게 이동했는데 정작 은행·쇼핑몰·업무 사이트에 로그인하려니 비밀번호가 보이지 않는 상황이 생길 수 있습니다. 반대로 비밀번호를 한꺼번에 내보내려다가 모든 사이트의 로그인 정보가 담긴 CSV 파일을 다운로드 폴더에 남기는 위험을 만들기도 합니다.

중요한 것은 비밀번호를 이동시키는 것 자체보다 새 저장소에서 안전하게 로그인 가능한지 검증하고, 불필요한 평문 파일을 남기지 않는 것입니다. 이 글은 2026년 11월 1일 기준 Google·Microsoft·Apple의 공식 지원 자료를 토대로, Chrome·Edge·Mac의 암호 앱 사이에서 비밀번호를 옮길 때 확인해야 할 순서를 정리했습니다. 메뉴 위치와 지원 범위는 버전 및 회사·학교 관리 정책에 따라 달라질 수 있습니다.

1. 먼저 결정할 것: 정말 CSV를 만들어야 하나요?

브라우저 또는 암호 관리자를 바꾼다고 해서 반드시 CSV 파일을 만들어야 하는 것은 아닙니다. 같은 PC에서 Chrome의 정보를 Edge로 가져오려면 Edge의 다른 브라우저에서 데이터 가져오기 기능을 먼저 검토할 수 있습니다. 반면 서로 다른 운영체제의 암호 관리자 사이에서 직접 가져오기가 지원되지 않는다면 CSV를 거치는 방식이 필요할 수 있습니다.

이동 상황먼저 고려할 방법확인 사항
Windows의 Chrome → 같은 PC EdgeEdge에서 Chrome 브라우저 데이터 직접 가져오기가져올 프로필과 암호 항목 선택
Chrome → Google 비밀번호 관리자 사용동일한 Google 계정 로그인·저장 범위 확인계정 저장과 기기 로컬 저장 구별
Edge → 다른 암호 관리자지원되는 직접 이동 기능부터 확인, 없으면 CSV다운로드된 평문 파일 관리
Chrome·Edge → Mac 암호 앱Mac 암호 앱의 지원되는 CSV 가져오기누락된 항목과 중복 확인
Mac 암호 앱 → 다른 서비스암호 앱의 내보내기 기능 이용 가능내보내지지 않는 항목 존재
회사·학교 관리 브라우저조직의 승인된 마이그레이션 방식내보내기 제한 및 개인정보 처리 정책

원칙: 직접 가져오기가 가능하면 평문 CSV 파일을 생성하지 않는 방법을 우선 검토합니다. 단, 직접 가져오기 역시 신뢰할 수 있는 기기에서 본인 계정으로 실행해야 하며 모든 항목이 이동했다고 자동으로 보장되지는 않습니다.

2. 비밀번호 이전 전에 해야 할 네 가지 점검

데이터 이전 작업을 시작하기 전에 이전 저장소, 새 저장소, 복구 경로, 기기 보안 상태를 확인하세요.

  1. 이전 저장소: 실제 비밀번호가 Chrome의 현재 프로필, Google 계정, Edge, Mac 암호 앱 중 어디에 저장돼 있는지 확인합니다.
  2. 새 저장소: 앞으로 자동 완성과 로그인에 사용할 브라우저 또는 암호 관리자를 정합니다.
  3. 복구 경로: 새 기기에서 계정 인증 요청이 뜨면 사용할 수 있는 전화번호·복구 수단이 현재 유효한지 확인합니다.
  4. 기기 보안: 회사 공유 PC, 공용 PC, 원격 접속 환경이 아닌 신뢰할 수 있는 기기에서 작업합니다.

여기서 가장 자주 놓치는 것은 브라우저에 로그인한 계정과 암호가 저장된 위치가 항상 일치하지 않는다는 사실입니다. Chrome은 Google 계정에 저장된 비밀번호와 기기에 로컬로 저장된 비밀번호를 구분할 수 있습니다. 따라서 Google 계정 로그인만 바꾼 뒤 저장된 암호가 모두 사라졌다고 판단하지 마세요.

또한 새 저장소로 옮겼다는 이유만으로 기존 저장소의 정보를 바로 삭제하면 안 됩니다. 최소한 대표적인 계정으로 로그인 테스트가 끝날 때까지는 이전 데이터를 남겨 두는 편이 안전합니다.

3. Chrome에서 비밀번호가 어디에 저장돼 있는지 찾기

Chrome에서 더보기 → 비밀번호 및 자동 완성 → Google 비밀번호 관리자로 이동하면 저장된 로그인 정보를 확인할 수 있습니다. 화면에서 계정 목록이 보이지 않는다면 Chrome에서 사용 중인 프로필이 의도한 프로필인지 확인하세요.

Google은 로그인한 계정에 비밀번호를 저장해 여러 기기에서 이용할 수 있고, 계정에 로그인하지 않은 상태에서는 기기에 로컬로 저장할 수도 있다고 설명합니다. 따라서 두 기기에서 같은 브라우저를 사용해도 비밀번호 목록이 다르게 보일 수 있습니다.

비밀번호를 옮기기 전에 아래 질문에 답해 보세요.

  • Chrome에 프로필이 둘 이상 있나요?
  • 어떤 Google 계정에서 저장된 비밀번호를 볼 수 있나요?
  • 새 기기에서 같은 계정으로 로그인했나요?
  • 자동 완성되는 비밀번호가 실제 계정의 최신 암호인가요?
  • 오래 전에 가입한 사이트 중 로그인 방식을 바꾼 곳이 있나요?

프로필 이름과 이메일 주소를 기록하는 것만으로도 잘못된 계정으로 내보내기·가져오기 하는 실수를 줄일 수 있습니다. 비밀번호 자체를 별도 메모장이나 스프레드시트에 복사해 기록할 필요는 없습니다.

4. Chrome에서 Edge로 옮길 때: 파일 없는 방법부터

두 브라우저가 같은 Windows PC에 설치돼 있다면 Edge의 브라우저 데이터 가져오기 기능을 먼저 확인하세요.

  1. Microsoft Edge를 엽니다.
  2. 설정 및 기타 → 설정을 선택합니다.
  3. 프로필 → 브라우저 데이터 가져오기로 이동합니다.
  4. Chrome에서 데이터 가져오기 항목을 찾습니다.
  5. 원하는 Chrome 프로필 및 가져올 항목을 확인합니다.
  6. 저장된 암호를 포함해 필요한 데이터만 선택합니다.
  7. 가져오기를 실행한 뒤 Edge의 저장된 암호 목록을 확인합니다.

Microsoft는 Chrome을 비롯한 다른 브라우저에서 즐겨찾기·암호 등을 Edge로 가져오는 기능을 공식 안내합니다. 화면의 항목과 선택지는 Edge 버전과 컴퓨터의 설치·관리 상태에 따라 달라질 수 있습니다.

가져오기를 완료했다는 알림은 각 사이트의 로그인 성공을 뜻하지 않습니다. 비밀번호 관리자에는 저장되어 있지만 해당 사이트에서는 비밀번호가 바뀌었거나 추가 인증을 요구할 수 있습니다. 중요한 서비스 몇 개를 직접 확인하는 단계가 필요합니다.

5. Chrome 암호를 CSV로 내보내는 절차

다른 서비스가 CSV 파일 가져오기만 지원한다면 Chrome의 공식 내보내기 기능을 이용할 수 있습니다.

  1. 개인 소유의 신뢰할 수 있는 컴퓨터에서 Chrome을 엽니다.
  2. 더보기 → 비밀번호 및 자동 완성 → Google 비밀번호 관리자로 이동합니다.
  3. 왼쪽 메뉴의 설정을 엽니다.
  4. 비밀번호 내보내기(Export passwords) 항목에서 파일 다운로드를 선택합니다.
  5. 요청되는 기기 인증을 진행합니다.
  6. 다운로드 위치를 확인하고 파일을 곧바로 대상 암호 관리자로 가져옵니다.
  7. 가져온 항목을 검증한 다음 CSV 파일을 삭제합니다.

CSV는 일반적인 데이터 교환용 파일입니다. 비밀번호가 들어 있는 CSV는 파일을 열 수 있는 사람에게 암호가 그대로 노출될 수 있는 고위험 자료입니다. Chrome 화면에서 보호되던 정보가 CSV 파일로 내려받아졌다고 해서 동일한 보호 수준이 유지되는 것은 아닙니다.

6. Edge 암호를 CSV로 내보내는 절차

Microsoft는 데스크톱 Edge에서 저장된 암호를 CSV로 내보내는 기능을 공식 지원합니다.

  1. PC에서 Microsoft Edge를 엽니다.
  2. 설정 및 기타 메뉴 또는 Alt+F로 메뉴를 엽니다.
  3. 암호(Passwords) 항목을 찾습니다.
  4. 암호 내보내기를 선택합니다.
  5. 표시되는 내보내기 확인 절차를 진행합니다.
  6. 파일 저장 위치를 지정합니다.
  7. 다른 암호 관리자로 가져온 뒤 CSV 파일을 삭제합니다.

Microsoft는 Android 또는 iOS용 Edge 앱에서는 저장된 암호 내보내기를 지원하지 않는다고 명시합니다. 모바일 앱에서 메뉴가 없다고 무작정 설정을 초기화하지 말고, 데스크톱 Edge에서 수행 가능한지 확인하세요.

Microsoft 역시 내보낸 CSV 파일은 보호되지 않는다고 경고하며 사용 후 삭제를 권장합니다. 회사나 학교가 관리하는 Edge는 조직의 정책에 따라 관련 기능이 제한될 수 있습니다.

공식 출처: Microsoft — Edge에서 암호 내보내기

7. Mac의 암호 앱에서 내보내고 가져오기

Apple은 Mac의 암호(Passwords) 앱에서 개별 웹사이트·앱의 암호 또는 모든 암호를 CSV 파일로 내보내는 기능을 제공합니다. 또한 다른 암호 관리자가 내보낸 CSV를 암호 앱으로 가져올 수 있도록 안내합니다.

Mac에서 내보내기

  1. Mac에서 암호 앱을 엽니다.
  2. 하나의 계정을 옮길 때는 해당 항목을 선택한 후 파일 → 선택한 암호를 파일로 내보내기를 확인합니다.
  3. 전체 암호를 옮기려면 파일 → 모든 암호를 파일로 내보내기 기능을 이용합니다.
  4. 저장 위치를 지정한 후 파일이 다른 사람에게 노출되지 않도록 관리합니다.

Mac 암호 앱으로 가져오기

  1. 사용하던 암호 관리자에서 CSV를 내보냅니다.
  2. Mac의 암호 앱을 엽니다.
  3. 파일 → 파일에서 암호 가져오기를 선택합니다.
  4. CSV를 지정해 가져오기를 실행합니다.
  5. 가져오지 못한 항목이 있는지 확인합니다.
  6. 정상적으로 가져온 뒤 CSV를 삭제합니다.

Apple은 가져온 암호가 암호 앱에 이미 있는 암호를 대체하지 않으며, 가져오지 못한 암호를 검토할 수 있다고 안내합니다. 기존 저장소의 암호가 자동으로 최신값으로 교체될 것이라고 가정하지 마세요.

Mac 암호 앱에서 내보내지지 않는 정보도 있습니다. Apple은 Wi-Fi 암호, 일부 그룹 공유 암호, Apple로 로그인 계정에 대한 접근 정보는 해당 CSV 내보내기에 포함되지 않는다고 설명합니다.

8. 비밀번호 CSV가 위험한 이유: 보관 위치보다 파일 내용이 문제

평소 브라우저에 저장된 암호는 해당 암호 관리자의 보안 기능을 통해 관리됩니다. 그러나 CSV로 내보내면 보호되지 않은 문자 데이터로 처리될 수 있습니다. 파일을 열 수 있는 사람이나 프로그램이 웹사이트 주소·사용자 이름·비밀번호를 확인할 수 있다는 뜻입니다.

행동위험 또는 고려 사항

평문 CSV를 전송하거나 오래 보관하지 않는 것이 핵심입니다. 필요하다면 오프라인의 신뢰할 수 있는 장치에서 짧은 시간 동안만 사용하고, 작업을 마치면 내보낸 파일과 그 사본을 모두 확인하세요.

이 표의 위험 분석은 공식 문서의 '내보낸 CSV는 암호화되지 않는다'는 설명을 바탕으로 구성한 실무용 예방 지침입니다.

9. CSV를 Google 비밀번호 관리자로 가져오는 방법

Google은 다른 암호 관리자에서 내보낸 CSV 파일을 Google 비밀번호 관리자로 가져오는 기능을 공식 안내합니다.

  1. 먼저 이전 암호 관리자에서 CSV 파일을 준비합니다.
  2. 컴퓨터에서 Chrome을 열고 Google 비밀번호 관리자 → 설정으로 이동합니다.
  3. 비밀번호 가져오기 항목의 파일 선택을 누릅니다.
  4. CSV를 선택하고 화면의 안내에 따라 가져옵니다.
  5. 가져오기가 끝나면 목록의 일부 항목을 검증합니다.
  6. 사용한 CSV 파일은 기기에서 삭제합니다.

Google의 공식 문서에 따르면 CSV의 헤더에는 일반적으로 url, username, password라는 열 이름이 있어야 합니다. 다른 암호 관리자가 서로 다른 열 이름을 사용하면 가져오기 오류가 발생할 수 있습니다.

단, 실제 비밀번호를 포함한 CSV를 불필요하게 스프레드시트에서 열어 두거나 온라인 편집 도구에 업로드하지 마세요. 형식 점검이 꼭 필요하다면 신뢰할 수 있는 로컬 환경에서 최소한의 범위로 확인해야 합니다.

Google은 한 번에 가져올 수 있는 암호 수와 계정 전체 저장 한도가 있다고 설명합니다. 공식 문서의 안내 수치는 한 번에 3,000개, Google 계정 전체 최대 10,000개입니다. 대량 계정이라면 가져오기 성공 여부와 누락 목록을 별도로 검증해야 합니다.

출처: Google — Google 계정으로 비밀번호 가져오기, Google — Chrome 암호 이전 안내

10. Edge에 CSV 암호를 가져올 때 확인할 것

다른 브라우저에서 Edge로 직접 가져오기가 되지 않거나 CSV로 이전해야 하는 경우, Microsoft는 파일 기반 암호 가져오기 절차도 제공합니다.

  1. Edge에서 설정 및 기타 → 설정을 엽니다.
  2. 프로필 → 브라우저 데이터 가져오기로 이동합니다.
  3. 기타 가져오기 위치에서 암호 가져오기를 찾습니다.
  4. 가져올 원본으로 암호 CSV 파일을 선택합니다.
  5. 파일을 지정한 후 가져오기를 완료합니다.
  6. 저장된 암호 목록에서 대상 항목들이 추가됐는지 확인합니다.

Microsoft는 CSV에서 가져온 비밀번호가 Edge에 저장된 비밀번호 목록에 추가된다고 안내합니다. 하지만 같은 사이트의 로그인 정보가 중복될 때 어떤 항목이 선택될지는 실제 저장 상태에 따라 확인해야 합니다.

가져오기 완료 후 바로 기존 암호 관리자 전체 삭제를 수행하지 마세요. 중요한 계정의 로그인 성공을 확인하고, 추가 인증 수단까지 정상 작동하는지 살펴본 다음 정리하세요.

출처: Microsoft — Edge 암호 CSV 가져오기

11. 옮겨지지 않는 것이 정상일 수 있는 항목

비밀번호 관리자에는 비밀번호 외에도 패스키, 인증 코드, 자동 완성 정보, 비밀번호 메모, 사이트별 추가 설정이 보관될 수 있습니다. 하지만 비밀번호를 CSV로 옮겼다는 사실만으로 이런 모든 정보가 이전된다는 보장은 없습니다.

특히 Google은 비밀번호와 패스키 관련 이전 기능을 제공하지만, 어떤 플랫폼에서 어떤 방식으로 이전할 수 있는지는 기능별로 다릅니다. CSV 파일 하나를 모든 패스키·인증코드의 보편적 백업 파일로 취급하면 안 됩니다.

중요한 계정은 기존 기기가 정상 작동하는 동안 새 기기에서 로그인할 수 있는지 직접 확인해야 합니다. 인증 앱이나 보안키를 잃어버린 상황이라면 비밀번호만 옮겨서는 로그인할 수 없을 수도 있습니다.

12. 가져오기는 성공했는데 로그인이 안 되는 네 가지 이유

비밀번호 목록이 정상적으로 표시돼도 해당 웹사이트에 로그인되지 않을 수 있습니다. 이것을 무조건 이전 실패로 판단하기보다 원인을 구분하세요.

① 저장된 암호가 이미 오래된 경우

이전 브라우저에 예전 비밀번호가 저장돼 있으면 새 브라우저로 옮겨도 여전히 예전 암호입니다. 실제 사이트에서 비밀번호를 변경한 뒤 저장소 갱신이 이루어졌는지 확인하세요.

② 잘못된 웹사이트 주소로 저장된 경우

같은 서비스라도 로그인 주소가 여러 개이거나 도메인이 변경됐을 수 있습니다. Google은 가져온 항목의 앱·사이트 이름이 예상한 필드에 들어가지 않을 수 있으므로 검색 기능으로 확인하라고 안내합니다.

③ 로그인 계정이 여러 개인 경우

개인 계정과 업무 계정이 같은 사이트에 저장돼 있으면 자동 완성 목록에서 다른 계정을 선택했을 수 있습니다. 실제 사용자 이름과 대상 사이트를 비교하세요.

④ 추가 인증이 필요한 경우

문자 메시지, 인증 앱, 보안키, 패스키 같은 추가 인증 수단이 요구될 수 있습니다. 암호가 정확하더라도 다른 인증 수단이 준비되지 않으면 로그인이 완료되지 않습니다.

테스트를 위해 기존 비밀번호를 대량 변경할 필요는 없습니다. 신뢰할 수 있는 기기에서 일부 중요한 계정의 로그인 가능 여부를 확인하고 이상이 있을 때 해당 서비스의 공식 복구 절차를 따르세요.

13. '성공적으로 이전했다'고 판단하는 10분 검증표

가져오기 알림이나 암호 목록의 개수만으로 작업을 마무리하지 마세요. 데이터 이전의 목적은 숫자가 아니라 실제 로그인 가능 상태입니다.

14. CSV 삭제는 끝이 아니라 '사본 확인'까지가 마무리

모든 공식 문서가 강조하는 중요한 부분은 CSV 파일 정리입니다. Google과 Apple은 사용 후 CSV 삭제를 안내하며, Microsoft는 Edge에서 내보낸 파일이 보호되지 않는다는 사실을 경고합니다.

  1. 대상 암호 관리자에서 대표 사이트의 로그인 성공을 확인합니다.
  2. 다운로드 폴더 및 내보내기 때 선택한 저장 위치를 확인합니다.
  3. 필요 없어졌다면 평문 암호 CSV를 삭제합니다.
  4. 별도 복사본이나 전송본이 있는지 확인합니다.
  5. 휴지통에 남아 있다면 적절하게 정리합니다.
  6. 클라우드 동기화 폴더나 백업에 사본을 만든 적이 있는지 살펴봅니다.

여기서 주의할 점이 있습니다. Windows에서 Shift+Delete로 휴지통을 거치지 않고 삭제하더라도 저장 장치·백업·동기화 기록에 존재했던 모든 사본이 영구적으로 소거됐다고 보장할 수는 없습니다. 중요한 것은 내보낸 뒤 불필요하게 전송·복사·보관하지 않는 것입니다.

이전에 비밀번호 CSV를 메일에 첨부하거나 공개된 저장소에 올린 사실이 확인됐다면, 단순 삭제만으로 위험이 사라졌다고 보지 말고 노출 가능 범위를 판단해 주요 계정의 비밀번호 변경과 세션·2단계 인증 점검을 고려하세요.

출처: Microsoft — 암호 CSV 내보내기 경고, Google — 암호 CSV 삭제 권고

15. 이전 작업이 끝난 후에는 '취약한 암호'도 점검

비밀번호를 옮기는 것은 계정을 보안 점검할 기회이기도 합니다. 같은 비밀번호를 여러 사이트에서 사용하거나 유출된 비밀번호를 그대로 보관해 왔다면 새 저장소에도 위험이 이전됩니다.

Google 비밀번호 관리자는 저장된 비밀번호 중 유출·취약·재사용 가능성이 있는 비밀번호를 점검하는 기능을 제공합니다.

Chrome에서 **더보기 → 비밀번호 및 자동 완성 → Google 비밀번호 관리자 → 진단(Checkup)**으로 이동해 확인할 수 있습니다. 지원되는 환경에서는 유출된 비밀번호 변경을 도울 수 있는 기능도 있습니다.

다만 비밀번호 관리자에서 저장된 문자열만 수정하는 것과 실제 서비스에서 비밀번호를 변경하는 것은 다른 일입니다. 실제 서비스에서 새 비밀번호로 변경이 성공했는지 확인한 다음 저장된 정보를 갱신하세요.

특히 주요 이메일 계정은 다른 서비스의 비밀번호 초기화 메일을 받는 수단일 수 있으므로 각별히 관리해야 합니다.

공식 출처: Google — 유출된 비밀번호 진단

16. 실제로 많이 생기는 세 가지 이전 시나리오

사례 A. Windows 노트북을 바꾸면서 Chrome에서 Edge로 옮기는 경우

새 노트북에 Chrome과 Edge가 모두 있다면 먼저 저장된 암호가 실제로 Chrome 프로필에 존재하는지 확인하세요. Edge에서 지원하는 다른 브라우저에서 가져오기 기능이 가능하다면 CSV 없이 이전하는 방법을 우선 고려합니다. 가져오기 후 Edge의 암호 목록과 몇 개 주요 계정의 로그인을 확인합니다.

사례 B. 오래 사용한 Windows PC에서 새 Mac으로 옮기는 경우

Chrome 또는 Edge의 공식 내보내기 기능을 거쳐 Mac 암호 앱에 CSV로 가져올 수 있습니다. 이때 CSV를 메신저나 일반 이메일에 첨부해 새 Mac으로 보내지 않는 편이 안전합니다. 신뢰할 수 있는 전송·저장 방식으로 최소한의 사본만 사용하고, Mac에서 수입한 비밀번호 목록을 검증한 다음 CSV를 정리합니다. 이전 Windows PC는 데이터 이전 검증이 끝날 때까지 폐기·초기화하지 않습니다.

사례 C. Google 계정 두 개를 쓰다가 새 PC에서 비밀번호가 부족한 경우

기존 Chrome에는 개인 Google 계정에 저장된 비밀번호, 다른 Google 계정에 저장된 비밀번호, 기기에만 저장된 비밀번호가 혼재할 수 있습니다. 이 경우 곧바로 CSV를 만들기보다 어느 프로필·저장소에 어떤 계정이 있는지 먼저 확인해야 합니다. 저장 위치와 대상 계정을 구분하지 않으면 옮겼다고 생각한 뒤에도 필요한 사이트가 누락될 수 있습니다.

세 시나리오의 공통점은 '최대한 빨리 모두 내보내기'보다 저장 위치 → 안전한 이전 방식 → 로그인 검증 → CSV 정리 순서를 지키는 것입니다.

17. 이전 실패 시 확인할 질문

Q1. 비밀번호 CSV를 엑셀로 열어 확인해도 되나요?

기술적으로 열 수 있는 경우가 있지만 비밀번호가 평문으로 표시될 수 있으므로 권하지 않습니다. 업무 공유나 온라인 문서 편집을 위해 업로드하는 것은 특히 피하세요. 형식 문제를 확인해야 한다면 공식 암호 관리자 지침에 따라 필요한 최소 범위만 신뢰할 수 있는 로컬 환경에서 점검하세요.

Q2. Chrome 암호를 옮겼는데 Edge 로그인 창에 자동 완성이 안 뜹니다.

Edge에 항목이 실제 저장됐는지, 현재 Edge 프로필이 맞는지, 사용자 이름과 웹사이트 주소가 맞는지 확인하세요. 저장된 데이터의 존재와 자동 완성의 동작은 구분해 점검해야 합니다.

Q3. Chrome 비밀번호 CSV를 Google 비밀번호 관리자로 가져올 때 오류가 나면?

Google의 공식 지침에 따라 CSV 파일 형식, 헤더의 url·username·password 열, 가져오기 한도, 원본 데이터의 정상 여부를 확인하세요. 실제 암호 파일을 타인에게 보내서 오류를 진단받지 마세요.

Q4. Mac 암호 앱으로 가져오면 기존 암호가 바뀌나요?

Apple은 가져온 암호가 이미 암호 앱에 저장된 암호를 대체하지 않는다고 설명합니다. 따라서 중복된 계정이 있다면 가져온 뒤 어떤 항목이 정확한지 검토할 필요가 있습니다.

Q5. Apple로 로그인한 사이트도 CSV로 모두 옮길 수 있나요?

그렇게 가정하면 안 됩니다. Apple은 Mac 암호 앱의 CSV 내보내기에 Apple로 로그인한 계정에 대한 접근 정보가 포함되지 않는다고 설명합니다. 해당 서비스의 다른 로그인·계정 관리 방식이 필요한지 확인하세요.

Q6. Edge 휴대폰 앱에서 비밀번호 내보내기 메뉴가 없습니다.

Microsoft는 Android·iOS Edge 앱에서 저장된 암호 CSV 내보내기를 지원하지 않는다고 안내합니다. 모바일 메뉴를 찾는 데 시간을 쓰기보다 데스크톱 Edge에서 가능한 경로를 확인하세요.

Q7. 비밀번호를 옮기면 2단계 인증도 자동으로 이전되나요?

비밀번호 이전과 인증 앱·패스키·보안키·백업 코드의 이전은 별도 문제입니다. 새 기기에서 추가 인증을 완료할 수 있는지 확인해야 합니다. 이전 기기에서 2단계 인증 정보를 바로 삭제하지 마세요.

Q8. 다운로드했던 CSV를 삭제했으니 100% 안전한가요?

그렇다고 단정할 수 없습니다. 평문 CSV가 다른 위치에 복사되거나 클라우드·메일·백업에 남아 있을 수 있습니다. 불필요한 사본 여부를 살피고, 이미 유출 가능성이 있다면 중요한 계정부터 보안 조치를 취하세요.

Q9. 수백 개 암호를 옮길 때는 모두 하나씩 로그인해야 하나요?

모든 계정의 즉시 재로그인이 현실적이지 않을 수 있습니다. 주요 이메일, 금융, 업무, 복구에 쓰이는 계정부터 실제 로그인 확인을 권하고, 나머지는 목록의 누락·중복 상태를 점검하세요. 다만 확인하지 않은 항목을 모두 검증 완료로 표시하면 안 됩니다.

최종 정리: 비밀번호 이전은 '파일 이동'이 아니라 '계정 접근 검증'

브라우저를 바꿀 때 안전한 순서는 다음과 같습니다.

  1. 비밀번호가 어느 프로필·계정에 저장돼 있는지 확인합니다.
  2. 브라우저 간 직접 가져오기 기능이 있는지 먼저 살펴봅니다.
  3. CSV가 필요한 경우에만 신뢰할 수 있는 기기에서 생성합니다.
  4. 새 암호 관리자로 가져오고 누락된 항목을 확인합니다.
  5. 이메일·금융·업무 등 주요 계정의 실제 로그인을 검증합니다.
  6. 패스키·2단계 인증·백업 코드 등 별도 복구 수단도 확인합니다.
  7. 불필요한 평문 CSV와 사본을 정리합니다.
  8. 이후 유출·재사용 암호를 점검하고 필요한 계정의 비밀번호를 변경합니다.

'가져오기 성공'은 곧 '계정 이전 완료'가 아닙니다. 새 브라우저에서 로그인할 수 있고, 기존 복구 수단도 준비돼 있으며, 내보낸 평문 파일이 안전하게 정리돼 있을 때 이전 작업을 마무리했다고 판단할 수 있습니다.
