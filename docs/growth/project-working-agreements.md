# 프로젝트 작업 합의

## 실행 방식

- `emfls.github.io`의 같은 유형 단일 페이지 SEO·정확성·수익 개선 작업은 현재 작업에서 직접 실행하는 인라인 방식을 기본값으로 사용한다.
- 동일한 실행 방식 선택을 페이지마다 다시 묻지 않는다.
- 사용자가 이미 승인한 범위에서는 테스트, 페이지 수정, 메인 배포, 공개 검증, Search Console 색인 요청, 성장 로그 기록까지 연속 처리한다.
- 외부 권한 확대, 파괴적 작업, 정책·법률·사실관계의 중대한 불확실성처럼 결과를 materially 바꾸는 새 결정이 생길 때만 사용자 확인을 요청한다.
- 적용 내용은 설계서, 구현 계획, 성장 로그에 계속 기록한다.

## 성과 원칙

- 일 수익 100달러는 보장값이 아니라 장기 목표로 관리한다.
- 페이지별 작업은 검색 클릭과 실제 검색 세션, 참여, 페이지뷰, 예상수익, 페이지 RPM을 28일 단위로 검증한다.
- 하루 예상수익 변동과 자동화로 의심되는 Direct 트래픽은 성장 근거로 사용하지 않는다.
- 성과가 없는 페이지 유형은 같은 방식으로 무한 확장하지 않고 키워드·콘텐츠 전략을 재검토한다.
- 검색 색인에 등록되지 않은 페이지는 검색 유입과 광고수익을 만들기 어렵다고 간주한다. 콘텐츠 생성·개선보다 먼저 `indexable 여부 → 사이트맵 포함 → 허브 내부링크 → 실제 색인/노출`을 확인한다.
- 신규·개선 페이지의 성과 평가는 색인된 날짜 이후부터 시작한다. 미색인 기간을 콘텐츠 성과 부진으로 잘못 해석하지 않는다.

## 작업 이력 관리

- 매 작업에서 변경 파일, 목적, 검증 결과와 다음 측정일을 `docs/growth/`의 날짜별 로그에 기록한다.
- 다음 요청을 처리하기 전에 작업 합의와 최신 성장 로그를 확인하여 이미 완료된 작업을 반복하지 않는다.
- 대량 변경보다 5페이지 단위 실험을 우선하며, 색인·검색 클릭·페이지 수익이 확인된 형식만 확대한다.
