# 전체 페이지 분류 및 내부 링크 설계

## 결론

현재 사이트는 개별 페이지의 본문 개선보다 **발견 구조가 먼저**다. HTML 18,867개 중 canonical과 robots 기준으로 기술적 색인 후보는 18,852개지만, 다른 HTML 페이지에서 들어오는 고유 내부 링크가 없는 후보가 11,298개(59.9%)다. 고립 페이지의 97.0%인 10,956개가 여행 콘텐츠다.

영어 루트 여행과 일본어 여행은 각각 5,385개 중 5,384개가 고립되어 있다. 한국어 여행은 고립이 188개로 적지만 5,413개 중 5,395개가 내부 링크 1개 이하라 구조가 취약하다. 따라서 모든 페이지에 동일한 관련 링크를 붙이기보다 언어별 여행 허브 → 국가 허브 → 도시 문서의 계층을 만들고, 도시 문서끼리는 같은 국가 안에서 문맥형 링크를 연결해야 한다.

## 측정 기준

- 분석 시점: 2026-08-12 저장소 `main`
- 단위: 저장소의 모든 `*.html`
- 기술적 색인 후보: canonical 1개가 있고 `noindex`가 아니며 운영·검증·테스트로 분류되지 않은 페이지
- 내부 유입 링크: 다른 HTML 문서의 정적 `<a href>`가 해당 canonical로 연결되는 고유 출발 페이지 수
- URL 정규화: Unicode NFC, `index.html` 제거, 끝 슬래시 통일, 쿼리·프래그먼트 제외
- 한계: 이는 Search Console의 실제 색인 상태가 아니라 저장소 링크 그래프다. JavaScript로만 생성되는 링크와 외부 백링크는 포함하지 않는다.

## 권장 내부 링크 구조

### 1. 여행: 언어 → 국가 → 도시 구조

```text
홈
└─ 언어별 여행 허브
   ├─ 지역·국가 목록
   │  └─ 국가 허브
   │     ├─ 도시 문서 A
   │     ├─ 도시 문서 B
   │     └─ 도시 문서 C
   └─ 테마 허브(혼자 여행·데이트·맛집·계절)
```

- 영어, 일본어, 한국어를 섞지 않고 같은 언어 안에서 연결한다.
- 여행 허브는 모든 도시 5,000개를 직접 나열하지 않고 국가 허브로 연결한다.
- 국가 허브는 해당 국가 도시를 최대 100개 단위로 나누고, 많으면 페이지를 분할한다.
- 각 도시 문서는 `여행 허브 1개 + 국가 허브 1개 + 같은 국가 관련 도시 3개`를 정적 `<a href>`로 연결한다.
- 관련 도시 3개는 고정 원형 연결 또는 인접 도시·여행 목적을 이용해 모든 문서가 최소 2개 이상의 다른 문서에서 유입되게 한다.

### 2. 칼럼: 주제 및 연도 아카이브

- 칼럼 메인에서 AI·경제·기술·건강 등 주제 아카이브로 연결한다.
- 주제 아카이브는 발행 연도 또는 50~100개 단위 페이지로 분할한다.
- 각 칼럼은 같은 주제의 최근·관련 글 3개와 주제 아카이브를 연결한다.
- RSS는 최신 발견 보조로 유지하지만 내부 링크를 대체하지 않는다.

### 3. 게임·도구: 언어별 완전 목록과 횡링크

- 각 언어의 게임 허브가 실제 게임 상세 전체를 빠짐없이 나열하도록 한다. 현재 LadderGame 계열처럼 허브에서 누락된 페이지를 제거한다.
- 각 도구는 같은 목적의 도구 3~5개를 연결한다. 예: 텍스트, 이미지, 코드, 계산기, 변환기 묶음.
- 번역 버전은 언어 전환용으로만 연결하고 관련 콘텐츠 영역에는 같은 언어 페이지를 우선한다.

### 4. 금융·Windows·기타 가이드: 소주제 클러스터

- 종목·코인·SEC·Windows 문제 유형별 허브를 기준으로 5~20개 문서 클러스터를 만든다.
- 각 문서는 상위 허브와 같은 클러스터의 3개 문서를 연결한다.
- 전 페이지 공통 푸터 링크나 무관한 인기 글 링크로 숫자만 늘리지 않는다.

## 링크 품질 규칙

- 모든 색인 대상 상세 페이지: 고유 내부 유입 최소 2개, 권장 3개 이상
- 상세 페이지의 내부 링크: 상위 허브 1개와 관련 문서 3~5개
- 허브 한 페이지: 링크 최대 약 100개, 초과 시 국가·주제·페이지네이션으로 분할
- 홈에서 상세 18,000개를 직접 연결하지 않고 핵심 언어·주제 허브만 연결
- 앵커 텍스트는 페이지 언어에 맞는 설명형 문구를 쓰고 동일 키워드 반복을 피함
- 링크는 Google이 바로 해석할 수 있는 실제 `<a href>` 사용
- 배포 계약: 깨진 링크 0, 고립 상세 0, 기술적 색인 후보의 95% 이상이 유입 2개 이상, 홈에서 상세까지 클릭 깊이 4 이하

## 실행 우선순위

1. 영어 여행 5,385개: 국가 허브와 관련 도시 링크 생성
2. 일본어 여행 5,385개: 동일 구조를 일본어로 생성
3. 한국어 여행 5,413개: 기존 단일 유입을 국가·테마 클러스터로 강화
4. 고립 칼럼 312개: 주제·연도 아카이브 연결
5. 게임 325개와 도구 499개: 언어별 허브 완전성 및 관련 항목 링크
6. 전체 재검사 후 고립 허브 4개와 기타 고립 16개 개별 처리

수익 우선 실행에서는 영어 여행과 한국어 여행을 먼저 처리하고 일본어는 다음 묶음으로 두는 편이 낫다. 색인 발견만 최우선이면 고립 수가 같은 영어·일본어 여행을 연속 처리하는 편이 낫다.

## 적용 전 주의사항

기술적 색인 후보 18,852개가 모두 색인할 가치가 있다는 뜻은 아니다. 내부 링크를 대량 추가하기 전에 내용이 거의 같은 도시·언어 페이지, 손상 문서, 얇은 페이지를 별도로 검사해 통합·제외 후보를 걸러야 한다. 품질이 낮은 페이지까지 강하게 연결하면 크롤 효율만 떨어질 수 있다.
