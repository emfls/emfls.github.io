# 검색 수요 기반 도구 3종 설계

## 목표

Google 검색 경쟁 분석에서 진입 가능성이 확인된 한국어 도구 3개를 독립 URL로 발행한다. 정적인 대량 콘텐츠가 아니라 사용자의 입력에 따라 결과가 달라지고 다시 방문할 이유가 있는 도구를 제공한다.

## 페이지 구성

### 캠핑 준비물 체크리스트

- URL: `/kor/util/camping-packing-checklist/`
- 입력: 인원, 숙박일, 계절, 캠핑 유형
- 출력: 수면·취사·의류·안전·위생 범주별 준비물
- 기능: 항목 체크, 브라우저 저장, 초기화, 인쇄
- 안전: 장소의 야영·취사 허용 여부는 별도로 공식 운영처에서 확인하도록 안내한다.

### 일본 eSIM 데이터 사용량 계산기

- URL: `/kor/util/japan-esim-data-calculator/`
- 입력: 여행일수, 하루 지도·메신저·SNS·음악·영상 사용량, 테더링 여부
- 출력: 총 예상 GB, 20% 여유를 포함한 권장 구간(1·3·5·10GB 또는 무제한 고려)
- 계산식과 앱별 사용량 가정을 화면에 공개한다.
- 특정 eSIM 판매사를 우선 추천하거나 구매·통신 품질을 보장하지 않는다.

### 일본 여행 준비물 체크리스트

- URL: `/kor/util/japan-travel-packing-checklist/`
- 입력: 계절, 여행일수, 위탁수하물 여부, 어린이 동반 여부
- 출력: D-30·D-7·D-1 준비 일정과 서류·결제·통신·의류·전자기기 목록
- 기능: 항목 체크, 브라우저 저장, 초기화, 인쇄
- Visit Japan Web 등 변동 정보는 공식 확인 링크와 확인일을 표시한다.

## 공통 설계

- 모바일 우선 단일 HTML 페이지이며 외부 프레임워크나 신규 의존성을 추가하지 않는다.
- 계산·목록 생성 로직은 별도 JavaScript 파일로 분리해 Node 기반 테스트가 가능하게 한다.
- JavaScript가 비활성화돼도 검색자가 핵심 설명과 기본 목록을 읽을 수 있다.
- canonical, 한국어 메타데이터, Open Graph, GA4 `G-QP5Q67GE5B`, 기존 AdSense 게시자 ID를 적용한다.
- 광고 영역과 입력·계산·체크 버튼을 시각적으로 분리하고 클릭 유도 문구를 사용하지 않는다.
- 각 페이지에 Article/WebApplication 성격에 맞는 JSON-LD와 FAQ를 넣되 화면에 보이는 내용과 일치시킨다.
- 캠핑 도구는 캠핑 허브에, 일본 도구 2개는 서로와 관련 여행 페이지에 내부 링크한다.

## 데이터 흐름과 오류 처리

1. 사용자가 조건을 선택한다.
2. 순수 JavaScript 함수가 조건을 정규화하고 목록 또는 계산 결과를 반환한다.
3. 화면은 결과를 렌더링하고 체크 상태만 `localStorage`에 저장한다.
4. 숫자 입력이 비어 있거나 범위를 벗어나면 안전한 기본값과 한국어 오류 안내를 사용한다.
5. 저장소 접근이 차단돼도 도구 기능은 계속 작동하고 저장만 생략한다.

## 테스트

- 캠핑 목록: 계절·인원·숙박일·유형에 따른 필수 항목 포함과 중복 제거
- eSIM: 사용량 합산, 20% 여유, 구간 추천, 범위 밖 입력 처리
- 일본 여행 목록: 계절·위탁수하물·어린이 조건 항목과 중복 제거
- HTML 계약: canonical, GA4, AdSense, 제목, 설명, JSON-LD, 관련 링크 존재
- 수동 확인: 모바일 너비에서 입력·결과·인쇄 버튼과 광고가 겹치지 않는지 확인

## 성공 기준

- 모든 자동 테스트와 기존 관련 테스트가 통과한다.
- 세 URL이 내부 링크를 통해 발견 가능하고 canonical이 실제 URL과 일치한다.
- 14일 후 색인·최초 노출, 28일 후 노출·클릭·자연검색 세션을 각각 측정한다.
- 28일 내 노출 20회 이상 또는 자연검색 세션 5회 이상인 유형만 확장한다.
