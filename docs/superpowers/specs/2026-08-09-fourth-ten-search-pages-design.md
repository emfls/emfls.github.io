## 접근 방식

- 권장 방식인 검색 의도·정확성 우선 전면 정리를 적용한다. 메타태그만 바꾸는 방식보다 본문 신뢰도를 높이고, 대량 신규 페이지 생성보다 기존 노출을 활용한다.
- 홈페이지는 실제 제공 카테고리와 대표 콘텐츠 탐색을 명확히 하고 존재하지 않는 기능이나 과도한 전문성을 주장하지 않는다.
- 게임·도구는 실제 동작을 테스트하고 조작법, 제한, 개인정보·외부 통신을 정확히 설명한다. 슬래시 canonical을 일관되게 사용한다.
- 비자·여행·미국 법안은 최신 정부·공공기관 원문을 우선하며, 여행금지·입국 재량·시행일·변경 가능성을 첫 화면에서 숨기지 않는다.
- 모든 페이지는 `2026-08-09` 최근 확인일, canonical, GA4, AdSense, 적절한 WebPage/WebApplication/VideoGame 및 FAQPage 구조화 데이터, 모바일 광고 폭 보호, 관련 내부 링크를 갖춘다.

## 검증과 배포

- 페이지군별 전용 테스트를 먼저 실패시킨 뒤 구현한다.
- 전체 회귀 테스트, 공통 우선 페이지 검증기, JavaScript 구문 검사, `git diff --check`를 적용 가능한 범위에서 실행한다.
- 변경 내용과 기준 노출을 성장 로그에 저장한다.
- main에 커밋·푸시하고 GitHub Pages 성공 및 공개 페이지 한 곳 이상을 확인한다.
- 검색 성과는 즉시 보장하지 않으며 2026-09-06에 같은 URL의 클릭·노출·CTR·순위와 GA4·AdSense를 비교한다.

## 자체 검토

- 미정 항목 없이 대상 URL과 공통 완료 기준을 고정했다.
- 기존 게임·도구 기능은 유지하고 사실 오류나 실행 오류만 테스트와 함께 수정한다.
- 10개 독립 페이지라는 범위 안에서 공통 검증·기록·배포를 하나의 실행 묶음으로 처리한다.
