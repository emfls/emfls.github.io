# 검색 유입·수익 개선 순차 반영 설계

작성일: 2026-08-01

## 목적

Google Search Console과 GA4에서 이미 성과가 확인된 페이지부터 개선해 실제 검색 방문과 AdSense 수익을 늘린다. 운영 중인 `main` 브랜치에 직접 반영하되, 각 작업을 작게 나누고 검증과 복구 지점을 유지한다.

## 성공 기준

- 수정 페이지가 기존 URL과 canonical을 유지한다.
- HTML, 내부 링크, 구조화 데이터에 치명적인 오류가 없다.
- 모바일 첫 화면에서 핵심 답을 빠르게 확인할 수 있다.
- 공식 출처와 최근 확인일을 제공한다.
- 수정 전후 28일의 GSC·GA4·AdSense 지표를 비교할 수 있다.
- 운영 배포가 실패하면 이전 커밋으로 복구할 수 있다.

## 반영 순서

### 단계 0: 측정과 안전장치

1. 현재 `main` 커밋을 작업 시작 기준점으로 기록한다.
2. GA4 측정 ID와 AdSense 게시자 ID가 우선 페이지에 일관되게 포함됐는지 검사한다.
3. Direct 및 `/kor/report/` 이상 트래픽은 저장소에서 확인 가능한 측정 코드·중복 태그·호스트 설정부터 점검한다.
4. 외부 로그나 Google 제품 설정이 필요한 항목은 코드 변경과 구분해 작업 기록에 남긴다.

### 단계 1: 첫 번째 검색 개선 묶음

1. 청주 캠핑
2. 루마니아 비자
3. 슬로바키아 비자
4. 카타르 비자
5. 노르웨이 비자

### 단계 2: 두 번째 검색 개선 묶음

1. 세르비아 비자
2. 슬로베니아 비자
3. 담양 캠핑
4. 김포 캠핑
5. 아산 캠핑

### 단계 3: 후속 후보

가평·안동·부산·광주·고흥 캠핑과 북마케도니아·스위스·나이지리아·르완다·우크라이나 비자를 같은 검증 절차로 처리한다.

## 페이지 변경 규칙

### 검색 요소

- 기존 URL과 canonical은 변경하지 않는다.
- 제목은 핵심 검색어, 지역 또는 국가, 사용자가 원하는 답을 앞부분에 둔다.
- 메타 설명은 대상, 체류 또는 이용 조건, 최신 확인 여부를 구체적으로 표현한다.
- Open Graph와 Twitter 제목·설명을 검색 제목과 일치시킨다.
- 구조화 데이터의 `dateModified`를 실제 수정일로 갱신한다.

### 본문 요소

- 제목 바로 아래에 짧은 결론 요약과 최근 확인일을 둔다.
- 캠핑 페이지는 위치, 이용 가능 여부, 주차, 화장실, 취사·화기, 예약, 현장 변동 가능성을 구분한다.
- 비자 페이지는 대한민국 여권 소지자 기준 단기 체류, 장기 체류, 필요 서류, 비용, 처리기간, 공식 신청처를 구분한다.
- 확인되지 않은 운영 상태, 무료 이용, 화기 허용, 비자 승인 가능성을 단정하지 않는다.
- 공식 정부·대사관·지자체·공공기관 출처를 우선 사용하고 확인일을 표시한다.
- 관련 페이지 2~4개와 상위 주제 허브를 문맥형 링크로 연결한다.

### 광고와 사용성

- 기존 AdSense 코드는 유지하되 핵심 답을 가리는 광고 배치는 추가하지 않는다.
- 모바일에서 제목, 요약, 핵심 표가 잘리지 않는지 확인한다.
- 불필요한 애니메이션이나 대규모 시각 개편은 이번 범위에서 제외한다.

## 데이터 흐름

1. GSC 노출·CTR·순위와 GA4 참여시간으로 작업 순서를 정한다.
2. 기존 HTML과 사이트 공통 패턴을 검사한다.
3. 시간에 민감한 사실은 공식 웹 출처로 재확인한다.
4. 페이지를 수정하고 로컬 정적 검사를 실행한다.
5. 변경 내역과 기준 수치를 마크다운 작업 기록에 추가한다.
6. 작은 단위로 커밋하고 `main`에 직접 푸시한다.
7. GitHub Pages 배포 상태와 공개 URL 응답을 확인한다.

## 검증

- 변경 파일의 HTML 파싱과 JSON-LD 구문 검사
- canonical, GA4, AdSense, 공식 출처, 내부 링크 존재 검사
- 로컬 링크 대상 파일 존재 여부 검사
- 변경 전후 diff에서 의도하지 않은 대량 변경이 없는지 확인
- 가능하면 프로젝트에 존재하는 기존 검사 또는 배포 워크플로 실행
- 푸시 후 GitHub Actions와 공개 페이지 응답 확인

## 오류 처리와 복구

- 사실 확인이 되지 않은 항목은 추측해 수정하지 않고 `확인 필요`로 표시한다.
- 검사 실패 시 푸시하지 않고 해당 페이지를 수정한다.
- 배포 실패 시 원인을 확인해 후속 커밋으로 수정한다.
- 공개 페이지에 치명적인 문제가 생기면 작업 시작 기준 커밋의 내용을 복원하는 커밋을 만들어 `main`에 푸시한다.

## 범위 밖 항목

- GA4·AdSense 계정 화면에서의 연결 설정
- GitHub Pages가 제공하지 않는 원본 방문 로그 분석
- 검색 노출과 수익 자료를 확인하지 않은 페이지의 대량 삭제
- 전체 사이트 디자인 교체
- 대량 신규 콘텐츠 자동 생성

## 측정 계획

각 페이지별 수정일과 수정 전 지표를 기록한다. 28일 후 다음 항목을 비교한다.

- GSC: 노출, 클릭, CTR, 평균순위
- GA4: Organic Search 세션, 참여율, 평균 참여시간
- AdSense: 페이지뷰, 예상 수익, Page RPM

CTR이 상대적으로 20% 이상 개선되거나 평균순위가 2계단 이상 상승하면 같은 방식의 확장을 우선한다. 클릭은 늘지만 참여시간이 낮아지면 제목과 본문의 검색 의도 일치를 다시 점검한다.
